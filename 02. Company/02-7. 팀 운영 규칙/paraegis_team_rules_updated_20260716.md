# paraegis Team Rules

최종 업데이트: 2026-07-16  
문서 성격: 팀 운영 규칙  
적용 대상: paraegis 팀원 전원

---

## 0. 문서 목적

이 문서는 **paraegis(파라이지스)**가 같은 기준으로 일하기 위한 내부 팀룰이다.

이 문서에는 일회성 실행 계획을 넣지 않는다.  
이 문서에는 팀이 반복적으로 지켜야 할 **원칙, 책임 기준, 소통 방식, 출퇴근 기준, 회고 방식**만 남긴다.

## 1. 팀 정체성

| 구분 | 기준 |
| --- | --- |
| 팀명 / 회사명 | **paraegis / 파라이지스** |
| 제품명 | **CrownOps / 크라운옵스** |
| 공식 표기 | **CrownOps by paraegis** |
| 첫 시장 | 치과기공소 |
| 핵심 방향 | 의료 현장의 의뢰 기반 업무에서 정보 누락과 불일치를 줄이는 운영 기술 |

### 1.1 paraegis의 의미

`paraegis`는 실무자의 곁에서 오류와 부담을 막아주는 운영 보호막이라는 의미를 가진다.

| 요소 | 의미 |
| --- | --- |
| para | 곁에서 보조하다, 보호하다, 방어하다 |
| aegis | 방패, 수호, 보호막 |
| paraegis | 실무자의 곁에서 정보 누락, 불일치, 책임 부담을 막아주는 운영 보호막 |

팀 정체성 문장:

> paraegis는 의료 현장의 실무자 곁에서 정보 누락, 불일치, 책임 부담을 줄이는 운영 기술 팀이다.

## 2. 미션과 비전

### 2.1 내부 미션

> 의료 현장에서 책임과 실무 부담을 떠안는 비의사 전문직이 더 안전하고 효율적으로 일할 수 있도록 돕는다.

이 미션은 단순히 프로그램 하나를 만드는 것이 아니라, 의료 현장에서 반복 확인, 정보 불일치, 책임 부담을 감당하는 실무자의 업무 환경을 기술로 개선하겠다는 팀의 문제의식이다.

### 2.2 외부 표현용 미션

> paraegis는 의료 현장의 의뢰 기반 업무에서 정보 누락과 불일치를 줄여, 실무자가 더 안전하고 효율적으로 일할 수 있는 운영 인프라를 만든다.

외부에서는 특정 직역과 대립하는 방식으로 말하지 않는다.  
핵심은 누군가와 싸우는 것이 아니라, 복잡한 협업 구조에서 실무자의 부담과 오류를 줄이는 것이다.

### 2.3 비전

> CrownOps를 시작으로 치과기공소의 제작 전 검증 표준을 만들고, 이후 의료 현장의 의뢰 기반 협업 문제를 해결하는 운영 인프라로 확장한다.

## 3. 제품 방향에 대한 팀 합의

CrownOps는 paraegis의 첫 제품이다.  
CrownOps는 치과기공소가 제작 전 의뢰서, STL 파일, 재료 조건을 확인해 **바로 제작 가능**과 **검증 필요**를 구분하는 제작 전 검증 체크게이트다.

### 3.1 CrownOps가 해야 하는 질문

> 이 케이스를 지금 제작해도 되는 상태인가?

### 3.2 CrownOps가 아닌 것

CrownOps는 아래로 포지셔닝하지 않는다.

| 하지 않는 것 | 이유 |
| --- | --- |
| 기공소 ERP | 기존 관리 프로그램과 충돌한다. |
| MES / 전체 공정관리 | 제작 전 검증보다 범위가 넓어진다. |
| 전자 의뢰서 플랫폼 | 치과 행동 변화와 법적 리스크가 커진다. |
| 의뢰서 OCR 솔루션 | 핵심 차별점이 흐려진다. |
| 청구·정산 프로그램 | 구매 이유가 달라진다. |
| CAD/CAM 자동화 도구 | 제품 범위가 무거워지고 기존 솔루션과 겹친다. |

### 3.3 제품 판단 기준

새 기능이나 문구를 넣기 전 아래 질문을 통과해야 한다.

| 질문 | 기준 |
| --- | --- |
| 제작 전 검증에 직접 도움이 되는가? | 아니면 보류한다. |
| 기공소가 이미 받는 의뢰서와 파일을 활용하는가? | 치과 행동 변화를 강제하지 않는다. |
| 기존 시스템을 대체하는가, 보완하는가? | 초기에는 보완재로 간다. |
| 작업자의 판단 부담을 줄이는가? | 단순 입력 업무를 늘리면 안 된다. |
| 외부에서 ERP/MES/OCR처럼 보이지 않는가? | 보이면 문구와 화면을 수정한다. |

## 4. 두 명 체제 운영 원칙

현재 팀은 소수 인원으로 움직이기 때문에, 한 사람의 침묵이 곧 팀 전체의 판단 공백이 될 수 있다.

### 4.1 대표의 역할

대표는 팀의 방향, 미션, 우선순위를 더 분명히 말해야 한다.  
팀원이 알아서 따라오기를 기대하지 않고, 왜 이 방향이어야 하는지 설명하고 설득한다.

대표의 책임은 다음과 같다.

| 책임 | 기준 |
| --- | --- |
| 방향 제시 | 팀이 지금 무엇을 가장 중요하게 봐야 하는지 말한다. |
| 맥락 공유 | 판단 배경과 문제의식을 숨기지 않는다. |
| 설득 | 단순 지시가 아니라 납득 가능한 이유를 제공한다. |
| 감정 조절 | 강한 피드백이 필요해도 상대가 방어적으로 굳지 않게 말한다. |

### 4.2 팀원의 역할

팀원은 단순 동의자가 아니다.  
대표의 의견을 듣고 따르는 것이 아니라, 자신의 관점에서 동의·반대·보완 의견을 적극적으로 제시한다.

팀원의 책임은 다음과 같다.

| 책임 | 기준 |
| --- | --- |
| 적극적 의견 제시 | 침묵하거나 “맞출게”로 끝내지 않는다. |
| 반대 의견 제시 | 방향이 약하다고 느끼면 즉시 말한다. |
| 실행 책임 | 맡은 일은 결과물 기준으로 끝낸다. |
| 문제 제기 | 팀이 느슨해지거나 방향이 흔들릴 때 먼저 말한다. |

### 4.3 공통 원칙

| 원칙 | 설명 |
| --- | --- |
| 침묵은 동의가 아니다 | 말하지 않은 불만은 나중에 문제 삼지 않는다. |
| 갈등은 회피하지 않는다 | 불편한 이야기를 미루는 것이 더 큰 리스크다. |
| 결정 후에는 따른다 | 충분히 말한 뒤 결정되면 실행에 집중한다. |
| 사람보다 문제를 본다 | 비난이 아니라 문제 해결을 목적으로 말한다. |

## 5. 피드백 규칙

피드백은 감정 해소가 아니라 팀의 성과를 높이기 위한 도구다.

### 5.1 피드백 기본 구조

피드백은 아래 순서로 말한다.

```text
상황 → 행동 → 영향 → 요청
```

예시:

```text
어제 회의에 말없이 빠진 상황이 있었고,
그로 인해 팀 일정과 신뢰 기준이 흔들렸어.
다음부터는 불참 가능성이 생긴 즉시 말해줬으면 해.
반복되면 팀 규칙에 따라 공식적으로 기록하자.
```

### 5.2 피드백 톤

| 구분 | 규칙 |
| --- | --- |
| 강한 피드백 | 필요하면 한다. 다만 인격 평가로 가지 않는다. |
| 방어적 반응 | 변명보다 사실 확인과 재발 방지를 먼저 말한다. |
| 사과 | 사과는 짧게 하고, 이후 행동 기준을 제시한다. |
| 종료 | 한 번 정리된 사안은 반복해서 끌고 가지 않는다. |

### 5.3 금지되는 피드백 방식

- 비꼬기
- 몰아붙이기
- 과거 일 반복 소환
- 상대 성격 단정
- “넌 원래 그래” 식의 일반화
- 말하지 않고 쌓아두었다가 폭발하기

## 6. 출퇴근 및 근무 규칙

### 6.1 기본 출근 기준

| 요일 | 기준 |
| --- | --- |
| 월요일~금요일 | **13:30 출근** |
| 토요일 | 공식 출근 및 정기 회의 없음 |
| 일요일 | **13:00 출근** |

토요일은 기본적으로 쉬는 날로 둔다.  
단, 발표 직전, 외부 행사 직전, 긴급한 고객 대응처럼 팀 합의가 필요한 경우에만 예외적으로 운영한다.

### 6.2 퇴근 기준

퇴근은 단순히 오래 앉아 있는 시간이 아니라, 그날의 핵심 결과물이 끝났는지를 기준으로 판단한다.

| 기준 | 내용 |
| --- | --- |
| 평일 | 기본적으로 저녁 시간까지 집중 근무한다. |
| 일요일 | 주간 정리와 회고를 마친 뒤 컨디션과 남은 업무를 보고 결정한다. |
| 공통 | 무리한 장시간 근무보다 지속 가능한 리듬을 우선한다. |

### 6.3 지각 기준

| 상황 | 규칙 |
| --- | --- |
| 10분 이상 늦을 것 같을 때 | 지연 예상 시점에 즉시 공유한다. |
| 30분 이상 늦을 것 같을 때 | 사유와 도착 가능 시간을 함께 공유한다. |
| 반복 지각 | 회고에서 원인을 확인하고 출근 루틴을 조정한다. |

지각의 핵심 문제는 늦는 것 자체보다 **말하지 않는 것**이다.

## 7. 개인 일정 및 결석 규칙

### 7.1 사전 공지 원칙

개인 일정은 숨기지 않고 미리 공유한다.

| 구분 | 규칙 |
| --- | --- |
| 예측 가능한 개인 일정 | 최소 **1주일 전** 공유한다. |
| 월 1회 수준의 개인 이벤트 | 가능하나 반드시 사전 공지한다. |
| 가족 행사, 장례식, 사고 등 돌발 상황 | 발생 즉시 공유한다. |
| 컨디션 문제 | 가능한 빨리 말하고, 당일 가능한 범위를 조정한다. |

### 7.2 결석 기준

결석은 반드시 명시적으로 공유해야 한다.  
상대의 일정, 분위기, 상황을 핑계로 스스로 결석을 정당화하지 않는다.

| 구분 | 기준 |
| --- | --- |
| 사전 공유 결석 | 사유와 복귀 시점을 명확히 말한다. |
| 당일 결석 | 발생 즉시 공유하고, 당일 대체 가능한 일을 정리한다. |
| 무단 결석 | 팀 신뢰를 훼손하는 중대한 위반으로 본다. |

### 7.3 무단 결석 및 반복 위반

무단 결석이 발생하면 해당 사안은 회고에서 정리한다.  
반복되면 **시말서 또는 반성문 제출**을 원칙으로 한다.

시말서에는 아래 내용을 포함한다.

```text
1. 발생한 일
2. 실제 원인
3. 팀에 준 영향
4. 재발 방지 기준
5. 다음에 같은 상황이 생기면 어떻게 행동할지
```

단, 한 번 정리되고 사과와 재발 방지 기준이 합의된 사안은 계속 끌고 가지 않는다.

## 8. 회의와 회고 규칙

### 8.1 정기 회의

정기 회의는 일요일 출근 후 진행한다.  
회의의 목적은 업무 나열이 아니라, 팀의 상태와 운영 기준을 점검하는 것이다.

정기 회의에서 다루는 내용은 다음으로 제한한다.

| 항목 | 질문 |
| --- | --- |
| 팀 상태 | 지금 팀이 느슨해졌는가, 과열됐는가? |
| 신뢰 | 지켜지지 않은 약속이 있는가? |
| 소통 | 말하지 않고 넘긴 불편함이 있는가? |
| 판단 | 제품 방향이나 팀 방향에서 흔들리는 지점이 있는가? |
| 컨디션 | 각자의 스트레스와 몰입 상태는 어떤가? |

### 8.2 회고 원칙

회고는 감정 배출 시간이 아니라 팀 운영 체계를 고치는 시간이다.

| 원칙 | 설명 |
| --- | --- |
| 솔직하게 말한다 | 좋은 말만 하지 않는다. |
| 문제를 개인화하지 않는다 | 문제의 원인과 구조를 본다. |
| 사과에서 끝내지 않는다 | 다음 행동 기준까지 정한다. |
| 정리된 일은 종료한다 | 반복 위반이 아닌 이상 계속 꺼내지 않는다. |

### 8.3 회고 템플릿

```text
# 주간 회고

## 1. 팀 컨디션
- 각자 현재 에너지와 스트레스 상태
- 창업에 대한 확신/회의감 정도

## 2. 약속 이행
- 지킨 약속
- 지키지 못한 약속
- 지키지 못한 이유

## 3. 소통 점검
- 말하지 못한 불편함
- 오해가 생긴 지점
- 더 빨리 말했어야 했던 것

## 4. 의사결정 점검
- 방향이 명확했던 결정
- 애매했던 결정
- 다시 합의해야 하는 기준

## 5. 팀룰 수정 필요 여부
- 추가할 규칙
- 수정할 규칙
- 삭제할 규칙
```

## 9. 커뮤니케이션 규칙

### 9.1 기본 채널

카카오톡 또는 팀 채팅을 기본 커뮤니케이션 채널로 사용한다.  
일반 메시지는 시간과 상관없이 보낼 수 있지만, 즉시 답장을 강요하지 않는다.

### 9.2 긴급 메시지

긴급한 경우에는 메시지 앞에 명확히 표시한다.

```text
[긴급] 오늘 안에 결정 필요
[확인 요청] 답장만 필요
[공유] 읽기만 해도 됨
[기록] 나중에 회고 때 참고
```

### 9.3 답장 기준

| 메시지 유형 | 답장 기준 |
| --- | --- |
| 긴급 | 가능한 즉시 확인 |
| 확인 요청 | 확인 후 짧게라도 답장 |
| 공유 | 즉시 답장 불필요 |
| 기록 | 회고 또는 문서 정리 시 참고 |

### 9.4 어려운 말 꺼내는 방식

불편한 이야기는 늦게 꺼낼수록 더 커진다.  
말하기 어려운 내용일수록 아래 문장으로 시작한다.

```text
이건 비난하려는 게 아니라 팀 기준을 맞추려고 말하는 거야.
```

```text
내가 느끼기엔 이 부분이 팀 운영상 위험해 보여.
```

```text
지금 말 안 하면 나중에 더 커질 것 같아서 먼저 말할게.
```

## 10. 의사결정 규칙

### 10.1 결정 방식

| 상황 | 방식 |
| --- | --- |
| 방향성 결정 | 대표가 최종 결정하되, 팀원 의견을 반드시 듣는다. |
| 실행 방식 결정 | 담당자가 제안하고 함께 조정한다. |
| 의견 충돌 | 각자 근거를 말한 뒤, 실험 가능한 방식으로 좁힌다. |
| 빠른 결정이 필요한 경우 | 임시 결정을 내리고, 이후 회고에서 수정한다. |

### 10.2 결정 기록

말로만 합의한 결정은 사라지기 쉽다.  
중요한 결정은 반드시 문서나 채팅에 남긴다.

기록해야 하는 결정은 다음과 같다.

- 팀룰 변경
- 제품 방향 변경
- 역할 변경
- 외부에 말하는 공식 문구 변경
- 출근/회의 기준 변경
- 책임 기준 변경

### 10.3 결정 후 태도

결정 전에는 적극적으로 반대할 수 있다.  
결정 후에는 실행에 집중한다.

단, 실행 중 명백한 문제가 발견되면 다시 제기할 수 있다.

## 11. 문서화 규칙

### 11.1 문서화가 필요한 것

| 항목 | 이유 |
| --- | --- |
| 팀룰 | 기준이 흔들리지 않게 하기 위해 |
| 회고 내용 | 같은 문제가 반복되지 않게 하기 위해 |
| 제품 정의 | 외부 설명이 흔들리지 않게 하기 위해 |
| 피드백 내용 | 감정이 아니라 개선 기준으로 남기기 위해 |
| 중요한 의사결정 | 기억 차이로 갈등이 생기지 않게 하기 위해 |

### 11.2 문서 작성 원칙

- 길게 쓰기보다 다시 볼 수 있게 쓴다.
- 감정보다 사실과 합의 기준을 남긴다.
- 누가 봐도 같은 의미로 읽히게 쓴다.
- 일정과 할 일은 별도 태스크 관리 도구에 둔다.
- 팀룰 문서에는 반복 규칙만 남긴다.

## 12. 생활 루틴과 지속 가능성

창업은 단기 몰입만으로 지속되지 않는다.  
팀은 오래 버틸 수 있는 생활 리듬을 중요한 운영 기준으로 본다.

### 12.1 식사와 컨디션

| 항목 | 기준 |
| --- | --- |
| 식사 | 출근 전 가볍게 먹거나, 필요한 경우 포장/도시락을 활용한다. |
| 저녁 | 상황에 맞게 유동적으로 해결하되, 끼니를 계속 놓치지 않는다. |
| 수면 | 수면 부족이 반복되어 팀 운영에 영향을 주지 않게 관리한다. |
| 음주 | 다음 날 업무와 약속에 영향을 주는 음주는 책임 위반으로 본다. |

### 12.2 번아웃 방지

| 원칙 | 설명 |
| --- | --- |
| 쉬는 날을 죄책감으로 만들지 않는다 | 쉬기로 한 날은 제대로 쉰다. |
| 무기력은 숨기지 않는다 | 회고에서 컨디션과 의심을 말한다. |
| 정체감은 문제로 다룬다 | 개인 탓이 아니라 팀 운영 신호로 본다. |
| 비교는 실행으로 바꾼다 | 다른 팀을 보고 위축되기보다 우리 행동 기준을 바꾼다. |

## 13. 심리 상태와 팀 분위기 관리

초기 창업팀에서는 제품 문제만큼 팀의 심리 상태가 중요하다.  
특히 정체감, 회의감, 느슨함은 숨기면 더 커진다.

### 13.1 회의감 다루기

창업에 대한 의심이 생기면 개인적으로만 끌어안지 않는다.  
회고에서 아래 기준으로 말한다.

```text
1. 지금 무엇이 막혔다고 느끼는가?
2. 이 회의감은 제품 때문인가, 실행 정체 때문인가, 컨디션 때문인가?
3. 우리가 실제로 안 한 것은 무엇인가?
4. 다시 작게 움직일 수 있는 기준은 무엇인가?
```

### 13.2 팀 분위기 원칙

| 원칙 | 설명 |
| --- | --- |
| 온실 속 팀이 되지 않는다 | 생각만 하지 않고 실제 사람을 만나는 방향을 유지한다. |
| 못하는 것과 안 한 것을 구분한다 | 실행하지 않은 것을 역량 부족으로 포장하지 않는다. |
| 응원은 구체적으로 한다 | “힘내자”보다 무엇을 다시 해볼지 말한다. |
| 무력감은 신호로 본다 | 팀 운영, 일정, 방향, 컨디션 중 무엇이 문제인지 분해한다. |

## 14. 팀룰 위반 처리 기준

팀룰 위반은 처벌이 아니라 신뢰 회복을 위해 다룬다.

| 단계 | 기준 |
| --- | --- |
| 1단계 | 당사자 간 바로 이야기한다. |
| 2단계 | 회고에서 사실과 영향을 정리한다. |
| 3단계 | 재발 방지 기준을 문서로 남긴다. |
| 4단계 | 반복되면 시말서 또는 반성문을 작성한다. |
| 5단계 | 계속 반복되면 역할과 팀 지속 가능성을 재검토한다. |

중요한 것은 실수 자체보다 **반복 여부와 회복 태도**다.

## 15. 최종 합의문

paraegis는 두 명이 각자의 부족함을 숨기지 않고, 팀의 기준을 계속 맞추며 CrownOps를 검증하는 팀이다.

대표는 방향과 미션을 분명히 말하고, 팀원은 단순 동의자가 아니라 적극적으로 의견을 낸다.  
팀은 불편한 이야기를 피하지 않고, 무단 결석과 침묵으로 신뢰를 흔들지 않는다.  
일정과 할 일은 별도 도구에서 관리하고, 이 문서에는 반복해서 지켜야 할 팀 운영 기준만 남긴다.

팀 공유용 한 문장:

> paraegis는 CrownOps를 만드는 과정에서 서로의 시간을 존중하고, 불편한 문제를 회피하지 않으며, 실무자의 부담을 줄인다는 미션에 맞게 작고 정확하게 실행하는 팀이다.
