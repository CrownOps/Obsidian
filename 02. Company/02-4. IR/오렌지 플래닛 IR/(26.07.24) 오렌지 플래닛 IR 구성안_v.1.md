# 슬라이드별 문구 완성본

## 1 — 표지

- **메인:** 고치기 전에 미리 막는 AI
- **서브:** 치과에서 촬영한 데이터가 쓸 수 있는 것인지, 보내기 전에 확인합니다
- **하단:** CrownOps by Paraegis — 치과·기공소 통합 검증 솔루션

---

## 2 — 산업 구조

- **카테고리:** 산업 구조
    
- **메인:** 보철물 하나에 두 개의 사업장이 협업합니다
    
- **서브:** 치과가 치아 형태를 만들어 보내면, 치과기공소가 그 데이터로 제작합니다
    
- **핵심 수치:** 전국 치과기공소 4,635개 (행정안전부, 2023)
    
- **도식:**
    
    ```
    환자 진료 → 치아 본뜨기·입안 3D 스캔 → [주문서 + 스캔 파일 전달]
    → 기공소 설계·제작 → 배송 → 환자 장착
          ↑                    ↑
       여기서 데이터가        여기서 그 데이터로만
         만들어지고            작업해야 한다
    ```
    
- **하단 설명:** 기공소는 환자를 직접 볼 수 없습니다(의료기사법상 대면 불가). 치과가 보낸 데이터가 유일한 정보원이고, 그 데이터가 잘못돼 있어도 기공소는 그것으로 만들 수밖에 없습니다. **이 비대칭이 이 자료가 다루는 문제의 출발점입니다.**
    

---

## 3 — 문제

- **카테고리:** 문제
- **메인:** 데이터는 치과에서 만들어지는데, 확인하는 사람이 없습니다
- **서브:** 촬영이 잘 됐는지 판단할 도구도, 판단할 사람도 없이 그대로 전송됩니다

### 오류가 넘어가는 과정

```
[치과]  촬영 → 확인 도구 없음 → 전송
                 ↑
        · 스캔은 대개 위생사가 수행하나 정식 교육 과정이 부재
        · 원장도 3D 데이터를 직접 판독하기 어려움
        · 본뜨기(인상)는 재료 특성상 촬영 시점에 이미 변형 발생

[기공소] 수신 → "이상한데?" → 그러나 묻기 어려움(거래 관계) → 일단 제작

[환자]  장착 실패 → 재제작 → 비용은 기공소가 부담
```

- **하단 설명:** 저희가 16곳 기공소와 교육기관 전문가에게 반복해서 들은 말은 같았습니다 — **"스캔이 잘못됐는지 확인할 방법이 애초에 없다."** 치과에서는 확인할 도구가 없고, 기공소에서는 확인해도 말하기 어렵습니다. 오류는 그 사이를 그대로 통과합니다.

---

## 4 — 문제의 크기

- **카테고리:** 문제의 크기
- **메인:** 원인은 앞에서, 비용은 뒤에서
- **서브:** 오류의 대부분은 치과 단계에서 생기고, 비용의 대부분은 기공소가 냅니다
- **수치 3개:**
    - 재제작 발생률 **10.1%** — 10개 중 1개 다시 제작
    - 가장 큰 원인 **63.7%** — **임상 단계(치아 본뜨기·입안 스캔) 오류**
    - 비용 부담 **67.4%** — **원인과 무관하게 기공소 부담**
- **각주:** 남신은(2018), 대한치과기공학회지 40(3)
- **실측:** 인터뷰 기공소 1곳 — 재제작 비용으로만 **월 약 80만원** 지출 (직접 확인)
- **하단 설명:** 이 세 숫자가 함께 있을 때 문제의 구조가 드러납니다. **오류를 만드는 쪽은 비용을 내지 않고, 비용을 내는 쪽은 오류를 막을 수단이 없습니다.** 그래서 저희 제품은 양쪽에 걸쳐 있어야 합니다. **→ 5p, 6p 참조**

---

## 5 — 왜 양쪽인가

- **카테고리:** 문제 정의
- **메인:** 한쪽만 고치면, 오류는 그대로 넘어갑니다
- **서브:** 기공소에서 아무리 잘 걸러도 이미 만들어진 오차는 되돌릴 수 없습니다

### 오류 발견 시점별 비용

|발견 시점|대응|비용|
|---|---|---|
|**치과 — 촬영 직후**|환자가 아직 진료실에 있음 → 즉시 재촬영|**거의 0**|
|기공소 — 접수 시|치과에 문의 → 재전송 대기 → 환자 재내원|납기 지연 + 확인 공수|
|기공소 — 설계 중|작업 중단 → 재확인|반나절 이상|
|치과 — 장착 시|전체 재제작|**건당 약 19~21만원** + 환자 재내원 + 거래처 신뢰|

- **핵심 문장:** **가장 싼 방어선은 환자가 아직 진료실에 있을 때입니다.**
- _가정: 월 200건 제작 · 재제작률 10%(업계 평균 10.1%) · 세라믹 크라운 기준_
- **하단 설명:** 기공소 단독 검증만으로는 "이 데이터는 쓸 수 없다"까지만 알 수 있고, 그때는 이미 환자가 진료실을 떠난 뒤입니다. 재촬영을 위해 환자를 다시 부르는 순간 치과도 손해를 봅니다. **촬영 직후에 알려주는 것이 양쪽 모두에게 가장 싼 해법입니다.** ※ 건당 손실 수치는 9p 가격 산정의 근거입니다.

## 6 — 솔루션 (통합) ★

- **카테고리:** 솔루션
- **메인:** 치과에서 한 번, 기공소에서 한 번
- **서브:** 기존 시스템은 건드리지 않습니다. 데이터가 넘어가는 길목 두 곳에 검증 게이트를 세웁니다

### 전체 흐름

```
┌─ 치과 ──────────────────────┐   ┌─ 기공소 ─────────────────────┐
│                              │   │                              │
│  촬영 (스캔 / 본뜨기)         │   │  수신                        │
│         ↓                    │   │         ↓                    │
│  ▣ GATE 1  촬영 품질 확인     │ → │  ▣ GATE 2  접수 조건 확인     │
│    "다시 찍어야 하나요?"       │   │    "지금 만들어도 되나요?"     │
│         ↓                    │   │         ↓                    │
│  통과분만 전송                │   │  제작 시작 판정               │
└──────────────────────────────┘   └──────────────────────────────┘
                                              ↓
                                     (장기) 배송 케이스 일치 확인
```

### GATE 1 — 치과: 촬영 품질 확인

|검증 항목|방식|구현|
|---|---|---|
|파일이 정상인가 (열림·손상·구멍)|규칙 기반|**현재**|
|촬영 범위가 요청 부위를 덮는가|규칙 기반|개발 중|
|맞물리는 반대쪽 치아(대합치)가 포함됐는가|규칙 기반|개발 중|
|보철물과 치아가 만나는 경계선(마진)이 명확한가|AI 분석|로드맵|
|무는 위치 기록(바이트)이 정합하는가|AI 분석|로드맵|

→ 결과: **재촬영 권장 / 확인 후 전송 / 전송 가능**

### GATE 2 — 기공소: 접수 조건 확인

|검증 항목|방식|구현|
|---|---|---|
|주문서·스캔 파일이 모두 도착했는가|규칙 기반|**현재**|
|같은 환자·같은 케이스가 맞는가 (환자·치아번호·작업명)|규칙 기반|**현재**|
|재료·색상(쉐이드) 정보가 확정됐는가|규칙 기반|**현재**|
|임플란트 위치 표시 부품(스캔바디) 정보가 있는가|규칙 기반|**현재**|

→ 결과: **제작 가능 / 검증 필요 / 외부(치과) 확인 필요 / 최종 확인 필요**

- **하단 설명:** 두 게이트는 같은 시스템입니다. 치과에서 확인한 결과가 기공소로 함께 넘어가고, 기공소는 "이 데이터가 어떤 확인을 거쳤는지"를 보면서 접수합니다. 문제가 있으면 **양쪽이 같은 화면을 보며 이야기**하게 됩니다 — 지금처럼 "느낌상 이상한데 말을 못 하는" 상황이 사라집니다.

## 7 — 구현 현황 · 로드맵 · 데이터 플라이휠

- **카테고리:** 제품 로드맵
- **메인:** 지금 되는 것과 만들고 있는 것을 나눠서 말씀드립니다
- **서브:** 규칙으로 잡을 수 있는 것부터 시작해, AI가 필요한 판단으로 올라갑니다

### ① 구현 현황

|구간|현재 구현|개발 중 (0~6개월)|로드맵 (1~2년)|
|---|---|---|---|
|**GATE 1 (치과)**|파일 유효성 검사|촬영 범위·반대쪽 치아 포함 여부 (규칙 기반)|경계선 명확도·무는 위치 정합 (AI)|
|**GATE 2 (기공소)**|도착·매칭·조건 완비 검증, 4단계 판정|치과 확인 결과 연동 표시|—|
|**확장**|—|—|배송 케이스 일치 / 스캐너·플랫폼 기업 연동|

### ② 데이터 플라이휠

```
        두 게이트 운영
              ↓
   반려·재촬영 사유 데이터 축적
   (어떤 촬영이 어떤 문제를 만드는가)
              ↓
   품질 판별 정확도 상승
              ↓
   재촬영 권장의 신뢰도 상승 → 치과 수용률 상승
              ↓
        (다시 위로)
```

- **핵심:** 규칙 기반으로 잡는 항목의 운영 기록이 AI 판별 모듈의 학습 자산이 됩니다. **1차 없이 2차로 바로 갈 수 없는 구조**이며, 이것이 후발주자 대비 시간 격차를 만듭니다.
- **하단 설명:** 저희가 지금 "AI가 모든 촬영 오류를 잡는다"고 말하지 않는 이유는, 그것이 아직 사실이 아니기 때문입니다. 규칙으로 판별 가능한 항목(파일 손상, 촬영 범위 누락, 반대쪽 치아 누락)부터 시작하고, 그 운영에서 나오는 데이터로 판단이 어려운 영역(경계선 명확도)으로 올라갑니다.

- **하단 설명:** 기공소 측 화면은 현재 구현되어 파일럿 준비 상태입니다. 치과 측 화면은 개발 중이며, 위생사가 촬영 직후 태블릿·모니터에서 즉시 확인하는 형태를 목표로 합니다.

## 9 — BM (수익모델) ★핵심

- **카테고리:** 수익모델
- **메인:** 치과가 쓰고, 기공소가 냅니다
- **서브:** 오류를 만드는 쪽과 비용을 내는 쪽이 다르기 때문에, 과금 구조도 그에 맞췄습니다

### ① 지불 구조

```
  기공소 ──── 월 구독료 ────→ CrownOps
     │
     └── 거래 치과에 무상 제공 ──→ 치과 (GATE 1 사용)
                                      │
                     검증된 데이터 ────┘
                            ↓
                        기공소 (GATE 2)
```

### ② 왜 이 구조인가

|주체|왜 쓰는가 / 왜 내는가|
|---|---|
|**기공소 (지불자)**|재제작 비용의 67.4%를 원인과 무관하게 부담 — 실측 월 약 80만원(1곳). 앞단에서 걸러질수록 직접 이득. 추가로, **거래 치과에 제공하는 서비스가 되어 영업 차별화 수단**이 됨|
|**치과 (사용자, 무상)**|비용 부담 없음. 재촬영을 위해 환자를 다시 부르는 번거로움과 체어타임 손실 감소. 촬영 직후라면 재촬영 비용이 사실상 0|
|**위생사 (실사용자)**|자신의 촬영이 적절한지 확인할 수단이 처음으로 생김|

### ③ 이 구조가 푸는 문제

> 기존에는 기공사가 원장에게 "스캔이 잘못됐습니다"라고 말해야 했고, 거래 관계상 대부분 말하지 못했습니다.  
> CrownOps에서는 **기공사가 아니라 시스템이, 그것도 전송 전에** 알려줍니다. 지적이 아니라 확인 절차가 됩니다.

|M|100~300건|**10만원 (기준가)**|
|L|300건 초과|15~20만원|

### ⑤ 가격 근거 — 앵커 3개

|앵커|산출|도출 가격|
|---|---|---|
|**① 절감액 역산**|월 200건 × 재제작률 10% = 20건 → 검증으로 방지 가능분 20%(보수적) = **월 4건** → 4 × 11~13만원 = **월 44~52만원 절감** → 가치 포착률 20~25%|**월 9~13만원**|

- **각주:** 앵커①의 "방지 가능 20%"는 보수적 가정입니다. GATE 1(치과 측)이 가동되면 재제작 원인의 63.7%를 차지하는 임상 단계 오류에 접근하므로 **상향 여지가 있으나, 검증 전까지는 보수적으로 유지**합니다.
- **하단 설명:** 가격을 확정하지 않은 것은 데이터가 없어서가 아닙니다. 이 시장의 기존 소프트웨어 지출은 월 2만원 수준이라 소프트웨어 벤치마크로는 값을 매길 수 없습니다. 가격은 재제작 절감액에서 역산해야 하고, 그 절감액은 파일럿에서만 측정됩니다. **→ 13p**

- **인용 표기 원칙:** 실명 대신 역할로 표기했습니다. 자료 제출 전 인용 당사자에게 사용 동의를 받고, 동의가 어려운 인용은 "인터뷰 공통 의견"으로 일반화할 것.

|H3|**기공소가 제공하면 치과는 GATE 1을 사용한다**|**통합 모델 성립의 전제**|미사용 → 기공소 단독 제품으로 축소 or 치과 직접 영업으로 전환|
|H4|절감 데이터를 본 소장은 유료 전환 의향을 밝힌다|수익모델 성립 + 가격 확정|전원 거절 → 가치 제안을 '소명 근거' 축으로 전환 검토|
|H5|촬영 품질 판별은 기술적으로 실현 가능하다|확장 서사의 기술 담보|데이터 확보 불가 → 교육기관 협력 구조 재설계|

## 월별 지표

**1~2개월차 (H1):** 기공소 파일럿 3~5곳 온보딩 / 누적 검증 케이스 수 / 발견률 기준선 / 발견 유형 분포 → GATE 1 우선순위 근거

**3~4개월차 (H2·H3):** 확인 시간 전후 비교 / 제작 전 반려 건수 / 방지 가능 비율 실측 / **거래 치과 대상 GATE 1 도입 제안 → 동의율·실사용률 측정** / 치과·위생사 인터뷰 5곳+

**5~6개월차 (H4·H5):** 절감 리포트 기반 유료 전환 제안 → 결과 전량 기록 / 가격 인터뷰(Van Westendorp 4문항 + 결재권자 확인) / GATE 1 규칙 기반 PoC / 관련 기업 제휴 미팅 1건+

# 부록 B. 예상 질문과 답

|질문|답|
|---|---|
|**치과가 왜 쓰나? 스캔이 잘못됐다고 지적당하는 건데**|지적이 아니라 촬영 직후의 확인 절차입니다. 환자가 진료실에 있을 때 알면 재촬영 비용이 사실상 0이지만, 나중에 알면 환자를 다시 불러야 합니다. 치과에게도 이득인 구조이며, 무엇보다 **비용을 내지 않습니다.** 다만 이 수용률은 저희가 6개월 안에 검증할 최대 리스크입니다(13p, 부록 A-H3).|
|**치과가 안 쓰면 어떻게 되나?**|GATE 2(기공소 측)는 단독으로도 작동합니다. 제품이 무용지물이 되는 것이 아니라 v3 수준의 기공소 단독 도구로 축소됩니다. 즉 **하방은 방어되어 있고 상방이 열려 있는 구조**입니다.|
|**왜 치과에서 돈을 안 받나?**|저희 인터뷰 판단으로는 치과는 재제작 비용을 기공소에 전가할 수 있어 지불 유인이 약합니다. 지불 유인이 실측으로 확인된 쪽(기공소, 월 약 80만원)에서 받고, 사용은 양쪽에서 일어나게 설계했습니다.|
|**가격 근거가 뭔가?**|앵커 3개 — ① 절감액 역산(월 4건 방지 = 44~52만원, 포착률 20~25% → 9~13만원) ② 인건비 대체(월 10시간 → 5만원) ③ 기존 소프트웨어 준거가격 2만원의 상한 압력. 수렴 구간 4~13만원에서 기준가 10만원. **(9p)**|
|**TAM이 작지 않나?**|단일가로 계산해서 그렇습니다. 층마다 가격을 올리면 숫자는 커지지만 검증 안 된 최고가를 전 세계에 곱한 값이 됩니다. 가격이 상향 검증되면 민감도 표의 공격 시나리오로 이동합니다. **(10p)**|
|**촬영 품질 AI는 언제 되나?**|규칙 기반 항목(촬영 범위·반대쪽 치아 포함 여부)은 개발 중이고, 경계선 판별 AI는 파일럿 데이터 확보 후 PoC입니다. 확정 일정보다 선행 조건을 밝히는 것이 정확합니다. **(7p)**|
|**스캐너 회사가 직접 하면 되지 않나?**|스캐너 기업은 자사 장비 데이터만 다루지만, 기공소는 여러 브랜드의 스캐너에서 데이터를 받습니다. **브랜드 중립적 검증**은 기공소 쪽에 서 있어야 가능합니다. 다만 저희는 스캐너 기업을 경쟁보다 **연동·라이선스 파트너**로 봅니다.|
|**기공소가 데이터를 줄까?**|환자 연계 파일이라 민감합니다. 그래서 GATE 2는 파일 내용이 아니라 도착·매칭·완비 여부라는 **메타 정보 중심**으로 설계했고, GATE 1 학습 데이터는 교육기관 채널(신구대 협의 중)을 병행 검토 중입니다.|
