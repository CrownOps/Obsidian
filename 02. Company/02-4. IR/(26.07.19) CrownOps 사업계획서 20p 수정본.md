## 1. 오프닝

### Slide 1. 잘못 만들기 전에 멈추게 하는 제작 전 검증 체크게이트

**핵심 메시지**

> CrownOps는 치과기공소가 CAD 작업 파일을 만들기 전에 의뢰서·스캔 파일·제작 조건을 확인해, 작업 가능한 케이스와 검증이 필요한 케이스를 구분합니다.

**본문**

치과에서 사용하는 크라운·브릿지·임플란트 보철물은 환자마다 다르게 제작됩니다. 치과는 의뢰서와 환자의 치아 스캔 데이터를 치과기공소에 보내고, 기공소는 이를 바탕으로 설계와 제작을 시작합니다.

하지만 실제 현장에서는 한 건의 정보가 종이·PDF·카카오톡·이메일·스캐너 플랫폼 등 여러 채널로 나뉘어 도착합니다. CrownOps는 흩어진 정보를 한 케이스로 묶고, 제작 전에 빠진 정보와 서로 맞지 않는 조건을 확인하는 검증 레이어입니다.

**권장 화면**

치과 → 여러 정보 채널 → CrownOps 검증 게이트 → CAD 작업 가능 / 검증 필요

### Slide 2. 사업 한 장 요약

| 구분 | 내용 |
|---|---|
| 문제 | 의뢰서·스캔 파일·재료·쉐이드·임플란트 정보가 분산돼 사람이 직접 맞춰 본다. |
| 고객 | 디지털 케이스가 많고 여러 작업자가 협업하는 치과기공소 |
| 해결 | 케이스별 정보 존재 여부와 일치 여부를 제작 전에 검증한다. |
| 결과 | 확인이 필요한 케이스만 빠르게 분리하고, 확인·변경 이력을 남긴다. |
| 수익 | 기공소 대상 월 구독형 B2B SaaS |
| 초기 검증 | 실제 기공소 케이스를 대상으로 예방 가능 오류율·확인시간·절감액·지불의향을 측정 |

**한 줄 정의**

> 기존 프로그램이 접수·청구·공정을 관리한다면, CrownOps는 실제 설계를 시작하기 전에 “이 케이스를 지금 만들어도 되는가”를 확인합니다.

## 2. 문제정의

### Slide 3. 문제 1 — 한 건의 주문이 여러 경로로 나뉘어 도착합니다

**핵심 메시지**

> 기공소가 받는 것은 하나의 완성된 주문이 아니라, 서로 다른 시간과 채널로 들어오는 정보 조각입니다.

**현장 흐름**

- 의뢰서: 종이, 사진, PDF, 메신저
- 스캔 파일: 3Shape, Medit, 이메일, 파일 서버
- 추가 요청: 카카오톡, 전화, 메모
- 제작 조건: 재료, 쉐이드, 치아번호, 임플란트·스캔바디 정보

담당자는 환자명·치과명·치아번호 등을 기준으로 이 정보가 같은 케이스인지 직접 판단합니다. 정보가 늦게 도착하거나 이름 규칙이 다르면 파일이 있어도 찾지 못하고, 다른 케이스와 잘못 연결될 수 있습니다.

**권장 화면**

한 환자 케이스를 중심으로 4~5개 채널에서 정보가 흩어져 들어오는 그림

---

### Slide 4. 문제 2 — 제작을 시작해도 되는지 판단하는 표준이 없습니다

**핵심 메시지**

> 현재의 검증 시스템은 프로그램이 아니라 숙련자의 기억과 습관입니다.

**현재 확인 방식**

1. 의뢰서가 있는지 찾는다.
2. 스캔 파일이 도착했는지 각 플랫폼을 확인한다.
3. 환자명·치아번호·작업 종류가 맞는지 눈으로 비교한다.
4. 재료·쉐이드·임플란트 정보를 다시 확인한다.
5. 애매하면 치과나 책임자에게 전화한다.

기공소마다 포스트잇, 수기 장부, 파일명 규칙, 담당자의 이중 확인 등 서로 다른 방식으로 대응합니다. 바쁜 시간에는 확인 단계가 생략되거나, 담당자가 바뀌면 기준도 함께 사라집니다.

**문제의 본질**

> 작업자의 부주의가 아니라, 제작 시작 조건이 구조화되어 있지 않은 프로세스 문제입니다.

---

### Slide 5. 문제 3 — 오류는 완성 후 발견되고, 손실은 현장에 남습니다

**핵심 메시지**

> 산업 전체의 재제작 문제 중 CrownOps는 제작 전에 확인 가능한 누락·불일치 오류를 우선 해결합니다.

2018년 전국 치과기공소 대표·임원 126명을 대상으로 한 예비조사에서는 치과보철물의 전체 재제작률이 10.1%, CAD/CAM 영역이 11.8%로 보고됐습니다. 원인과 무관하게 기공소가 재제작 비용을 부담한다고 응답한 비율은 67.4%였습니다.

다만 모든 재제작을 CrownOps가 막을 수 있는 것은 아닙니다. 임상 인상 오류, 환자 구강 상태 변화 등은 별도의 임상 문제입니다. CrownOps가 목표로 하는 것은 다음과 같은 **제작 전 예방 가능 오류**입니다.

- 정식 의뢰서 누락
- 스캔 파일 미도착·중복·오연결
- 환자명·치아번호·작업 종류 불일치
- 재료·쉐이드 누락 또는 상충
- 임플란트·스캔바디 정보 확인 누락

**핵심 문장**

> 오류는 전달 과정에서 발생하지만, 재제작 비용과 책임은 현장에 남습니다.

## 3. 해결책

### Slide 6. 해결책 — 제작 라인 앞에 디지털 검사대를 둡니다

**핵심 메시지**

> CrownOps는 업무 전체를 바꾸지 않고, CAD 작업 파일 생성 전 한 번의 검증 단계를 추가합니다.

**작동 흐름**

의뢰서·스캔 파일 수신
→ 같은 환자·작업의 정보로 케이스 묶기
→ 필수 정보 존재 여부 확인
→ 의뢰서와 제작 조건 비교
→ 상태 분류
→ 확인 및 변경 이력 저장

**상태값**

- **작업 가능**: 필요한 정보가 확인됨
- **검증 필요**: 정보가 애매하거나 작업자 판단이 필요함
- **외부 검증 요청**: 치과·거래처 확인이 필요함
- **최종 확인 필요**: 책임자 판단이 필요함

**포지셔닝**

> ERP나 MES를 교체하지 않습니다. 기존 업무와 CAD 사이에 검증 게이트를 추가합니다.

---

### Slide 7. 기능 1·2 — 케이스 통합과 규칙 기반 검증

#### 기능 1. 케이스 단위 정보 통합

- 의뢰서, STL·PLY 등 스캔 파일, 재료, 쉐이드, 임플란트 정보를 한 케이스에 연결
- 수취 채널과 도착 시점 기록
- 파일만 있고 의뢰서가 없거나, 의뢰서만 있고 파일이 없는 상태 표시

#### 기능 2. 제작 조건 검증

- 필수 항목 존재 여부 확인
- 환자명·치아번호·작업 종류 매칭
- 재료·쉐이드·임플란트 부품 조건 비교
- 거래처별·작업별 필수 체크 규칙 적용

**MVP 원칙**

초기에는 ‘모든 것을 AI가 자동 판단한다’고 약속하지 않습니다. 반복 가능한 항목부터 규칙 기반으로 검증하고, 실제 케이스에서 정확도를 측정하며 자동 매칭 범위를 확대합니다.

---

### Slide 8. 기능 3 — 예외만 분리하고 검증 이력을 남깁니다

**핵심 메시지**

> CrownOps의 가치는 모든 케이스를 더 입력하게 하는 것이 아니라, 위험한 케이스만 보이게 하는 것입니다.

#### 예외 처리

- 작업 가능 케이스는 바로 통과
- 누락·불일치 케이스만 검증 목록으로 분리
- 작업자 → 책임자 → 외부 검증 요청의 판단 경로 구조화

#### 검증 리포트

- 어떤 정보가 언제 도착했는가
- 어떤 항목이 누락·변경되었는가
- 누가 어떤 판단을 했는가
- 제작 시작 전 어떤 확인이 완료되었는가

**고객 가치**

1. 작업자: 확인할 대상을 빠르게 찾는다.
2. 소장: 모든 케이스를 직접 확인하지 않아도 된다.
3. 거래처: 책임 공방보다 사실과 변경 이력을 기준으로 소통한다.

**성과지표**

- 케이스당 확인시간
- 예방 가능 오류 탐지율
- 오경보율
- 제작 전 수정된 케이스 수
- 절감된 재작업 비용

## 4. 시장기회

### Slide 9. 전체 기공소가 아니라, 오류 비용이 커지는 기공소부터 시작합니다

**핵심 메시지**

> 초기 고객은 ‘디지털 장비를 가진 곳’이 아니라, 분산된 정보와 다중 작업자로 검수 부담이 커진 기공소입니다.

2023년 기준 국내에는 약 4,635개의 치과기공소와 약 1.9만 개의 치과병·의원이 존재하는 것으로 집계됐습니다. 치과보철물 제조 시장은 2021년 7,724억원에서 2027년 1조953억원으로 성장할 것으로 전망된 바 있습니다.

다만 제조시장 전체를 CrownOps의 소프트웨어 시장으로 보지 않습니다. 초기 이상적 고객은 다음 조건을 가진 기공소입니다.

- 월 디지털 케이스 물량이 많다.
- 작업자와 거래처가 여러 명·여러 곳이다.
- 이메일·메신저·스캐너 플랫폼 등 3개 이상의 수취 채널을 사용한다.
- 대표가 모든 케이스를 직접 검수하기 어렵다.
- 파일 누락·조건 불일치·재확인을 반복 경험한다.

**핵심 결론**

> 규모가 아니라 ‘검수 복잡도’가 초기 시장을 결정합니다.

---

### Slide 10. 시장규모는 고객 수와 검증된 가격으로 계산합니다

**핵심 메시지**

> 47억원을 확정 시장처럼 제시하지 않고, 타깃 비중과 가격을 분리한 시나리오로 관리합니다.

#### 고객 수 시나리오

- 전체 기준: 국내 치과기공소 약 4,635곳
- 초기 SAM 가설: 전체의 15~30%인 약 700~1,400곳
- 근거: 디지털 다중 작업자·다채널 수취·높은 검수 부담을 가진 기공소 비중에 대한 가설
- 해당 비중은 파일럿과 업계 설문으로 재산정

#### 매출 시나리오

- 목표 혼합 ARPU 가설: 월 25만원
- SAM 연매출 시나리오: 약 21억~42억원
- 3년 목표: 유료 기공소 110곳
- 3년 목표 ARR: 약 3.3억원

**주의 문구**

위 수치는 확정 시장규모가 아니라 가격·타깃 비중에 따른 사업 시나리오입니다. 최종 시장규모는 실제 사용량, 지불의향, 유료 전환율을 기반으로 업데이트합니다.

## 5. 경쟁현황

### Slide 11. 경쟁사가 없는 시장이 아니라, 검증이 중심 업무가 아닌 시장입니다

**핵심 메시지**

> 기존 업체도 의뢰·공정·소통 기능을 빠르게 확장하고 있습니다. CrownOps는 ‘제작 전 정보 검증’이라는 좁은 업무에서 더 깊어져야 합니다.

| 구분 | 주요 역할 | 현재 강점 | CrownOps의 차이 |
|---|---|---|---|
| Clever Lab | 의뢰서 등록, 청구·미수금, 통계, 운영관리 | 약 700개 기공소 도입 보도, 강한 유통·고객 기반 | 운영 전반이 아닌 제작 시작 조건 검증에 집중 |
| DENTALSOFT MES | 공정·매출·현장 운영 관리 | 실시간 공정 및 기공소 운영 | 공정 진입 전 누락·불일치 검증 |
| ALL-CONEC | 치과–기공소 의뢰, 주문·정산·진행, CAD·장비 연결 | 플랫폼·CAD·IoT 통합 | 치과 행동변화를 요구하지 않는 기공소 내부 검증 |
| Medit Link 생태계 | 치과–기공소 주문·파일 전달, CAD/CAM 앱 연동 | 스캐너 기반 글로벌 데이터 연결 | 여러 플랫폼 밖에서 들어온 정보까지 묶는 중립 검증 레이어 |
| Dentbird 등 CAD | AI 보철 설계 | 설계 속도와 자동화 | 설계 이전에 입력 조건이 맞는지 확인 |

**전략적 해석**

> ‘아무도 하지 않는다’가 아니라, 기존 업체가 부가 기능으로 다루는 검증 업무를 독립적인 핵심 제품으로 만든다는 전략입니다.

---

### Slide 12. 차별성은 기능 수가 아니라 검증 깊이와 도입 방식입니다

#### 가치 1. 제작 전 예외 탐지에 집중

기존 시스템의 첫 화면이 매출·청구·공정 현황이라면, CrownOps의 첫 화면은 **작업 가능 케이스와 검증 필요 케이스**입니다.

#### 가치 2. 기존 시스템을 대체하지 않는 얇은 레이어

기공소는 이미 파일 플랫폼, CAD, 관리 프로그램을 사용합니다. CrownOps는 이를 모두 바꾸게 하지 않고, 기존 흐름 사이에 검증 단계만 삽입합니다.

#### 축적되는 진입장벽

- 거래처별 필수 입력 규칙
- 재료·임플란트 부품·스캔바디 확인 규칙
- 실제 오류와 결과의 연결 데이터
- 기공소별 예외 처리 흐름
- Medit·이메일·파일 서버·기존 관리 프로그램 연동

**방어 논리**

> 단순 체크리스트는 복제할 수 있지만, 현장별 검증 규칙과 오류 결과 데이터가 누적된 워크플로우는 쉽게 교체하기 어렵습니다.

## 6. 비즈니스모델

### Slide 13. 무료 진단으로 손실을 보여주고, 구독으로 전환합니다

**핵심 메시지**

> 기공소가 소프트웨어 설명을 듣고 구매하는 것이 아니라, 자기 케이스에서 발견된 손실을 보고 구매하게 합니다.

#### 진입 상품

**20케이스 무료 프리체크**

- 의뢰서·파일 도착 현황
- 누락·불일치 항목
- 외부 검증 요청 건
- 확인에 소요된 시간
- 예방 가능 손실 추정 리포트

#### 유료 요금제 가설

| 요금제 | 월 요금 가설 | 대상 | 핵심 기능 |
|---|---:|---|---|
| Starter | 15만원 | 소규모 디지털 기공소 | 케이스 통합, 필수항목 검증, 기본 리포트 |
| Pro | 30만원 | 다중 작업자 기공소 | 승인 흐름, 거래처별 규칙, 팀 권한, 고급 리포트 |
| Partner | 50만원 이상 | 대형·네트워크 기공소 | 채널 연동, API, 맞춤 규칙, 관리자 분석 |

가격은 확정값이 아니라 파일럿에서 검증할 가설입니다. 요금제는 직원 수가 아니라 월 케이스 수·사용자 수·연동 범위로 구분합니다.

### Slide 14. 직접 판매형 B2B SaaS로 시작합니다

**고객 획득 흐름**

교수·학회·기공소 네트워크·업계 커뮤니티

→ 월 구독 전환
→ 동료 기공소 소개 및 파트너 확산

**핵심 영업지표**

- 프리체크 → 파일럿 전환율

- 고객 획득비용 회수기간

**법적·전략적 경계**

CrownOps는 특정 기공소에 환자나 주문을 알선하고 수수료를 받는 플랫폼이 아닙니다. 의뢰서 발행을 대체하지 않으며, 기공소 내부의 정보 검증과 기록을 제공하는 SaaS입니다.

## 10. 클로징

### Slide 20. 보철물 제작의 첫 공정은 설계가 아니라 검증이어야 합니다

> CrownOps는 더 빨리 만드는 프로그램이 아닙니다.  
> 잘못 만들기 전에 멈추게 하는 첫 번째 공정입니다.

한 건의 보철물에는 의뢰서, 스캔 파일, 재료, 쉐이드, 임플란트 정보와 여러 사람의 판단이 연결됩니다. 지금까지는 이 연결을 작업자의 기억과 책임감에 맡겨 왔습니다.

CrownOps는 그 판단을 표준화하고, 작업 가능한 케이스와 검증이 필요한 케이스를 제작 전에 구분합니다.

**6개월 실행 약속**

- 실제 기공소 3곳
- 누적 1,000케이스
- 예방 가능 오류·절감액 실측
- 최소 2곳 유료 전환

**최종 요청 문구 — 지원사업용**

> 본 사업의 선정을 요청드립니다. 지원기간 동안 실제 현장 데이터로 ‘발견한 문제’가 아니라 ‘방지한 손실’을 증명하겠습니다.
