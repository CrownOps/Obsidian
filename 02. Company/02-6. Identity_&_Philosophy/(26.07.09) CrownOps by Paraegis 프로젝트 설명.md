---

## 1. 프로젝트 개요

**CrownOps**는 치과기공소의 제작 전 오류를 줄이기 위한 B2B SaaS다. 개발·운영 주체는 모기업 **Paraegis**이며, 표기는 **"CrownOps by Paraegis"**를 사용한다.

CrownOps는 치과기공소가 디자인 작업에 들어가기 전, 의뢰서·STL 파일·재료·쉐이드·스캔바디 정보가 서로 맞는지 확인하는 **제작 전 정보 검증 체크게이트**다. 케이스를 접수·관리하는 시스템을 대체하는 것이 아니라, 디자인 작업 직전 단계에서 "지금 이 케이스를 작업해도 되는지"를 확인하는 보완 솔루션이다.

---

## 2. 미션 & 비전

**미션**
의료 현장에서 실무와 책임을 함께 짊어지는 전문가들 — 치과기공사, CAD/CAM 디자이너 — 이 더 안전하고 효율적으로 일할 수 있도록 돕는다.

**비전**
CrownOps를 시작으로, 의뢰(발주) 기반 업무 구조에서 발생하는 정보 불일치와 책임 부담을 줄이는 운영 인프라를 구축한다. 장기적으로는 치과기공 영역을 넘어 확장 가능한 형태를 지향한다.

---

## 3. 핵심 문제

치과기공소에는 의뢰서, STL 파일, 재료 조건, 쉐이드, 스캔바디 정보가 여러 채널(카카오톡, 이메일, 스캐너 연동 등)로 흩어져 들어온다. 이를 담당자가 수동으로 취합·확인하는 과정에서 오류가 발생한다.

| 문제 | 결과 |
|---|---|
| 의뢰서 누락 | 제작 근거 부족, 리스크 발생 |
| STL 파일 미도착·중복 | 작업 지연 |
| 의뢰서-STL 불일치 | 잘못된 케이스로 작업 진행 |
| 재료·쉐이드 정보 누락 | 치과 재확인 필요 |
| 스캔바디 정보 부족 | 디자인 작업 전 검증 지연 |
| 담당자 수동 확인 의존 | 휴먼에러 증가 |
| 오류 발견 시점이 늦음 | 리메이크, 납기 지연, 신뢰 저하 |

> **정보 누락·불일치 → 리메이크 → 납기 지연 → 신뢰 손상**으로 이어지는 구조적 문제다.

---

## 4. 제품 정의

> CrownOps는 치과기공소가 디자인 작업 전에 의뢰서, STL 파일, 재료 조건, 쉐이드, 스캔바디 정보를 확인해 **"작업 가능" / "검증 필요" / "재문의"** 케이스를 구분하는 제작 전 정보 검증 체크게이트다.

CrownOps는 ERP·MES가 아니며, 기존 운영 시스템을 대체하지 않는다. 기존 시스템과 함께 사용하는 **보완적 검증 레이어**로 포지셔닝한다.

---

## 5. 타깃 고객

- **핵심 타깃**: 한국 치과기공소 — 기공소장, CAD/CAM 디자이너
- 케이스 수가 많아 담당자 수동 확인 부담이 큰 기공소
- 여러 치과와 거래하며 의뢰 정보가 분산되는 기공소
- 리메이크를 줄이고자 하는 성장형 기공소

## 6. 핵심 기능

| 기능 | 설명 |
|---|---|
| 의뢰서 확인 | 정식 의뢰서 존재 여부 확인 |
| STL 파일 확인 | 파일 도착·중복·누락 여부 확인 |
| 의뢰서-STL 매칭 | 케이스 정보 기준 매칭 검증 |
| 재료 검증 | 제작 재료 정보 누락 확인 |
| 쉐이드 검증 | 쉐이드 정보 누락·불명확 여부 확인 |
| 스캔바디 정보 확인 | 스캔바디 관련 정보 부족 여부 확인 |
| 케이스 상태 분류 | 작업 가능 / 검증 필요 / 재문의로 구분 |

## 7. 현재 진행 상태

- **Go-to-market**: 기공소장 대상 직접 아웃리치(이메일·전화·무접촉 파일 요청)는 정체 상태. 원인은 담당자의 여력 부족과 환자 연계 파일에 대한 데이터 민감성 우려로 진단됨
- **전략 전환**: 신구대학교 치기공과와의 협업을 통해 교육 현장에서 데이터를 수집하고 제품을 고도화하는 방향으로 피벗 중. 가천대 네트워크를 통한 교수 소개가 진행 예정
- **랜딩페이지**: dentalsyncs.com 운영 중. 신뢰 신호(운영 주체 명시, 개인정보 처리방침, 연락처) 보강이 최우선 과제로 확인됨
- **브랜드 시스템**: Paraegis(모기업)와 CrownOps(제품) 브랜드 아이덴티티 구축 완료

---

## 8. 앞으로의 과제

1. 신구대학교 교수 연결 구체화 및 교육 현장 파일럿 데이터 수집 시작
2. 랜딩페이지 신뢰 신호(운영 주체, 개인정보 처리방침, 연락처) 보강
3. 랜딩페이지 내 범위를 벗어난 UI 목업(마진 라인, 크라운 핏 체크 등) 정리 및 "예시 화면" 라벨링 일관화
4. 파일럿 기공소 대상 검증 항목 현장 테스트
