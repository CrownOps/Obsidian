## 슬라이드 1 — 오프닝 후킹
> 목표: 30초 안에 청중 전체를 잡기 + 10초 산업 배경  
> v2.0 대비 변경: 수치 나열 전에 비유 1문장 추가 → "치과기공소를 모르는 청중"도 따라올 수 있게

### 시각화 구성
> **3분할 레이아웃** — 비유 / 수치 / 모순

```
┌──────────────────┬───────────────────────────┬───────────────────┐
│                  │   원인의 80.9%             │                   │
│  치과가 만들어   │    치과에서 발생            │  이 구조를 막는   │
│  달라고 한 치아  │         ≠                  │  검증 소프트웨어가 │
│  10개 중 1개는   │   비용의 67.4%             │  없었습니다.      │
│  다시 만들어집니다│    기공소가 부담            │                   │
│                  │                            │                   │
│     10.1%        │  [화살표 역방향 강조]       │                   │
└──────────────────┴───────────────────────────┴───────────────────┘
```

**발표 멘트 오프닝 (10초)**
> "치과에서 씌우는 인공 치아 — 보철물은 치과가 만들지 않습니다.
> 치과 옆 골목에 있는 치과기공소가 만듭니다.
> 그리고 그 주문 10건 중 1건은 처음부터 다시 만들어집니다."

**수치 출처** _(슬라이드 하단 작게)_
- 재제작율 10.1%, 원인 80.9%, 비용부담 67.4% — 대한치과기공학회지(남신은, 2018), 전국 기공소 126곳
- 국내 10% vs 글로벌(미국) 평균 3.8~4% — **국내가 2.5배 높다** → [[03. Reference/03-02. 보고서/(26.07.20) 리메이크 손실 정량화 리서치]]
- 재제작의 60%+는 생산 시작 **전** 단계에서 발생 — 처방전·파일·커뮤니케이션 오류 → [[03. Reference/03-02. 보고서/(26.07.20) 리메이크 손실 정량화 리서치]]

## 슬라이드 4 — 문제: 비용 모순 + "왜 아무도 안 만들었나"
> 목표: "얼마나 손해인가" + "왜 구조적으로 반복되는가" + **선제 답변**  
> v2.0 대비 변경: 스택 차트 제거, "왜 아무도 안 만들었나" 블록 추가 (심사에서 반드시 나오는 질문 선제 차단)

### 시각화 구성
> 상단: 파이 비교 + 손실 요약 / 하단: 구조적 이유 3가지

**[상단] 원인 vs 부담 파이 비교**
```
  [원인]                [비용 부담]
  치과 측                기공소 측
  80.9%          ≠       67.4%

  잘못은 치과에서 나오고, 비용은 기공소가 낸다.
  
  재제작 1건 손실: 최소 11만원 (재료비 8만 + 인건비 + 전기세 + 배달비)
  월 80만원을 외주 재제작비로 쓰는 기공소도 존재 (연간 약 1,000만원)
```

**[하단] 왜 아직 아무도 안 만들었나 — 3가지 구조적 이유**
```
① 법인 설립 불가 (의료기사법)
   → 지분 투자 차단 → 업계 자본 공백 → 스스로 해결 불가능

② 기존 SW는 다른 문제를 푼다
   → 장부·청구 관리 (월 2만원대) / 보철 설계 지원
   → '제작 전 정보 검증' 영역은 공백

③ 지금의 대응책은 개인 습관
   → 포스트잇 · 전화 재확인 · 한 번 더 보기
   → 사람이 바쁘면 무너짐
```

## 슬라이드 5 — 솔루션: Before / After + 신호등 UX
> 목표: "소프트웨어가 어느 단계에 들어가는지" + 실제 UX  
> v2.0 대비 변경: 신호등 🟢🟡🔴 명시, "검사대" 포지셔닝 강화

### 시각화 구성
> 2단 레이아웃 — 위: Before / 아래: After + 신호등

**[Before]**
```
치과 스캔 → 의뢰서(PDF) → 카카오톡 ···❌ 공백 ··· 수기 확인 → CAD → CAM → 납품
                                         ↑
                            담당자가 손으로 맞춰봄 → 바쁘면 건너뜀 → 재제작
```

**[After]**
```
치과 스캔 → 의뢰서 → 카카오톡 → ✅ CrownOps 검사대 → CAD → CAM → 납품
                                          ↑
                              흩어진 정보를 한 화면에 모아 자동 대조
                              
🟢 작업 가능      — 필요한 정보 모두 확인됨. 바로 제작 시작.
🟡 검증 필요      — 정보 애매함. 작업자 판단 후 진행.
🟠 외부 검증 요청 — 치과·거래처 확인 필요. 제작 전 재문의.
🔴 최종 확인 필요 — 책임자 판단 필요. 에스컬레이션.
```

**발표 멘트 포인트**
> "저희가 채운 건 제작 공정이 아닙니다.
> 제작 시작 전, 아무도 없었던 자리입니다.
> 기존 프로그램을 대체하지 않습니다 — 그 앞단에 검사대 하나를 추가하는 것입니다."

> 근거: 재제작의 60%+는 생산 시작 전 단계(처방전·파일·정보 오류)에서 발생 (VCAD)  
> → CrownOps가 개입하는 정확한 지점

> ⚠️ **Ver. B 수정 권고**: "주문 10건 중 1건을 CrownOps가 막는다"는 표현은 금지.  
> "재제작 중 제작 전 정보 오류로 인한 예방 가능 케이스"로 범위 한정.

## 슬라이드 8 — 경쟁 분석 + 해자

        ↓

        ↓                         ↓
