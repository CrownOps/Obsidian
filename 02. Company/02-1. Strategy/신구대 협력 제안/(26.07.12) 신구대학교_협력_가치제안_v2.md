# 신구대학교 협력 가치 제안 정리 (v2)

## 치기공 교육·연구를 위한 구조화 데이터 소스 공동 구축

> **v2 변경 사항**: 교수자 참여 부담 설계(6장), 데이터 거버넌스와 책임 구조(14장), 1단계 협력 제안(15장), 내부 전용 North Star 연결(22장) 신설. 구 팀명 표기 정정. 협력 전제 확정 반영 — 형태는 산학협력 MOU(계단식), 데이터셋은 공동 소유, 논문은 옵션.

---

## 1. 문서 목적

본 문서는 DentalSync가 신구대학교 치기공학과에 협력을 요청하는 과정에서, **신구대가 협력을 통해 얻을 수 있는 실질적인 가치가 무엇인지** 팀 내부에서 정리하기 위한 문서이다.

초기에는 신구대에 다음과 같은 데이터를 요청하는 방향으로 접근했다.

- 익명화된 치과기공물 제작의뢰서
- STL·PLY·OBJ 등 디지털 스캔 및 설계 파일
- 재료·쉐이드·임플란트 관련 제작 조건
- 교수자 기준의 `CAM 가능 / 확인 필요 / 재문의 필요` 판단

그러나 단순히 다음과 같이 접근해서는 협력의 명분이 약하다.

> “저희 제품을 검증하기 위해 데이터를 제공해 주세요.”
> 

신구대 입장에서 중요한 것은 다음 두 가지이다.

1. 왜 자신들이 시간과 데이터를 제공해야 하는가?
2. 그 결과 무엇이 교육과 연구 현장에 남는가?

따라서 이번 협력의 본질을 다음과 같이 재정의한다.

> **신구대는 실제 치기공 실습 케이스와 도메인 전문성을 제공하고, DentalSync는 이를 치기공학계가 교육과 연구에 활용할 수 있는 구조화된 데이터 자산으로 전환한다.**
> 

협력의 진행 전제는 다음과 같이 확정한다.

- 접점: 소개받은 교수님을 통한 1차 미팅
- 형태: 경량 파일럿 합의서로 시작해 산학협력 MOU로 확장
- 데이터셋: 공동 소유
- 논문: 옵션으로 제안 (필수 조건 아님)

---

# 2. 핵심 정의

## 한 문장

> **치기공 현장의 경험과 판단을, 학계가 연구하고 교육할 수 있는 데이터로 전환한다.**
> 

또는

> **신구대와 함께 치기공 교육·연구에 활용 가능한 실증 데이터 소스를 구축한다.**
> 

이번 협력의 핵심은 **단순한 데이터 제공 요청이 아니라, 치기공 교육 현장에서 발생하는 경험과 전문적 판단을 재사용 가능한 데이터 자산으로 만드는 것**이다.

---

# 3. 현재 치기공 분야의 데이터 문제

치기공 분야에는 다양한 연구와 통계가 존재한다.

예를 들어 다음과 같은 연구는 이미 이루어져 있다.

- 보철물 재제작률
- 주요 리메이크 원인
- 치과와 기공소 간 의사소통 문제
- 의뢰 정보 누락
- CAD/CAM 교육 경험
- 디지털 치의학 교육의 필요성

그러나 실제 제작 과정에서 발생하는 오류를 **하나의 케이스 단위로 처음부터 끝까지 연결한 데이터**는 상대적으로 부족하다.

현재 필요한 것은 다음 질문에 답할 수 있는 데이터이다.

- 오류는 정확히 어느 단계에서 발생했는가?
- 어떤 정보가 누락되었는가?
- 제작 전에 발견되었는가, 제작 후에 발견되었는가?
- 누가 오류를 발견했는가?
- 학생과 교수자의 판단은 어떻게 달랐는가?
- 해당 오류는 재문의, 수정, 재작업, 리메이크 중 무엇으로 이어졌는가?
- 어떤 정보가 있었다면 오류를 사전에 방지할 수 있었는가?

즉, 단순히

> “리메이크가 발생했다.”
> 

는 데이터가 아니라,

> **“어떤 케이스에서 → 어느 단계에서 → 어떤 오류가 발생했고 → 어떻게 판단되었으며 → 어떤 결과로 이어졌는가”**
> 

가 연결된 데이터가 필요하다.

# 5. 신구대가 제공할 수 있는 것

## 5.1 실습 케이스

신구대는 치기공 교육기관으로서 다음과 같은 실습 데이터를 보유할 가능성이 있다.

- 치과기공물 제작의뢰서
- STL·PLY·OBJ 파일
- 상악·하악·바이트 데이터
- 보철 종류
- 재료
- 쉐이드
- 임플란트 정보
- 스캔바디 정보
- 제작 결과물
- 수정 전·후 결과

---

## 5.2 교수자의 전문적 판단

단순한 파일만으로는 데이터의 가치가 제한적이다.

신구대 교수진은 실제 케이스를 보고 다음과 같은 전문적 판단을 제공할 수 있다.

- 이 케이스는 바로 제작 가능한가?
- 어떤 정보가 부족한가?
- 어떤 항목은 반드시 확인해야 하는가?
- 어느 수준에서 제작을 중단해야 하는가?
- 어떤 오류가 실제 제작 실패로 이어질 가능성이 높은가?

이를 다음과 같이 구조화할 수 있다.

| 상태 | 의미 |
| --- | --- |
| PASS | 현재 정보로 제작 가능 |
| CHECK | 담당자 또는 교수자 확인 필요 |
| REQUERY | 추가 정보 확보 전 제작 진행 불가 |

---

## 5.3 교육 과정에서 발생하는 오류

학생 실습 과정에서는 실제 산업 현장에서 체계적으로 확보하기 어려운 교육 데이터가 발생한다.

예를 들면 다음과 같다.

- 학생이 놓친 항목
- 교수자가 수정한 항목
- 반복적으로 발생하는 실수
- 학년별 판단 차이
- 보철 종류별 오류 차이
- CAD/CAM 단계별 오류
- 수정 전·후 결과
- 교육 전·후 판단 변화

이러한 데이터는 치기공 교육과 연구에 활용할 수 있는 중요한 데이터 소스가 될 수 있다.

---

# 6. 교수자 참여 부담 설계

가치 제안만으로는 부족하다. 교수자의 판단 제공은 실제 노동이므로, 부담의 크기를 먼저 계산해 보여주고 최소화 설계를 함께 제시한다.

## 6.1 부담의 실체

교수자에게 요청하는 것은 케이스당 다음 두 가지다.

1. PASS / CHECK / REQUERY 판단 1회
2. CHECK·REQUERY인 경우 부족 항목 지목 (오류 코드 선택)

자유서술을 요구하지 않고 선택형으로 구성하면 **케이스당 약 2~3분**을 목표로 할 수 있다. 케이스 30건 기준 총 1.5시간 내외이며, 이 수치를 제안 시 명시한다.

> `확인 필요` — 첫 미팅 전에 팀 내부에서 샘플 케이스 1건으로 실제 소요 시간을 측정해 수치를 확정한다.
> 

## 6.2 최소화 원칙

- **기존 실습 평가 흐름 안에서 수행한다.** 교수자가 어차피 실습 케이스를 검토하는 시점에 판단을 기록하도록 설계하며, 별도 세션을 요구하지 않는다.
- 판단 입력 양식(체크리스트 + 오류 코드 선택)은 DentalSync가 제작해 제공한다. 종이·스프레드시트·웹폼 중 교수자가 선호하는 형태를 따른다.
- 라벨 취합, 정합성 검토, 구조화는 전부 DentalSync가 수행한다. 신구대 측 후처리 작업은 없다.

# 7. DentalSync가 신구대에 제공할 수 있는 것

## 7.1 실습 오류 및 재작업 분석 데이터

DentalSync는 신구대의 실습 케이스를 구조화하여 다음과 같은 데이터를 만들 수 있다.

| 영역 | 분석 항목 |
| --- | --- |
| 의뢰 단계 | 치식, 재료, 쉐이드, 임플란트 정보 누락 |
| 파일 단계 | 상악·하악·바이트 파일 누락 |
| 매칭 단계 | 의뢰서와 파일의 케이스 불일치 |
| 버전 관리 | 중복 파일, 수정본, 구버전 혼입 |
| 임플란트 | 제조사, 시스템, 플랫폼, 스캔바디 불일치 |
| 제작 전 검증 | 학생과 교수자의 판단 차이 |
| 결과 | 재문의, 수정, 재작업, 리메이크 발생 |

이를 통해 신구대는 다음과 같은 질문에 답할 수 있다.

- 학생들은 어느 단계에서 가장 많이 실수하는가?
- 어떤 오류가 가장 반복되는가?
- CAD 기술의 문제인가, 제작 전 확인의 문제인가?
- 어떤 교육 항목을 강화해야 하는가?
- 학년이 올라갈수록 어떤 오류가 감소하는가?
- 숙련도가 올라가도 반복되는 오류는 무엇인가?

# 9. 단순 체크리스트가 아닌 교육용 검증 루브릭

신구대에 제공할 수 있는 핵심 교육 산출물은 단순 체크박스가 아니라 **학생의 판단 능력을 평가할 수 있는 루브릭**이다.

## 예시

| 검증 항목 | 학생 판단 | 시스템 판단 | 교수자 판단 | 실제 결과 |
| --- | --- | --- | --- | --- |
| 치식 | PASS | PASS | PASS | 정상 |
| Bite | PASS | CHECK | REQUERY | 파일 누락 |
| Scanbody | PASS | CHECK | REQUERY | 매칭 오류 |
| Shade | CHECK | CHECK | CHECK | 추가 확인 후 진행 |

이를 통해 다음을 분석할 수 있다.

- 학생의 판단 정확도
- 학생과 교수자의 판단 차이
- 반복적으로 놓치는 항목
- 교육 전·후 판단 능력 변화
- 시스템이 실제 교육 보조 도구로 활용 가능한지

즉, 단순히

> “학생이 CAD/CAM 프로그램을 사용할 줄 아는가?”
> 

를 평가하는 것이 아니라,

> **“학생이 실제 제작 가능한 케이스와 위험한 케이스를 구분할 수 있는가?”**
> 

를 교육하고 평가하는 것이다.

# 10. 치기공 오류 분류체계 구축

현재 리메이크나 제작 오류는 현장에서 다양한 표현으로 기록될 수 있다.

예를 들면 다음과 같다.

- 스캔이 이상함
- 파일이 잘못됨
- 의뢰가 부족함
- 기공 실수
- 재료 잘못 선택
- 다시 해야 함

이러한 자유로운 표현만으로는 데이터를 축적하고 비교하기 어렵다.

따라서 오류를 공통된 기준으로 분류할 필요가 있다.

# 13. 표현상의 주의점

## “치기공 업계에는 규격이 없다”라고 표현하지 않는다

치과·치기공 분야에는 이미 국제적으로 다양한 데이터 교환, CAD/CAM, 전자 의뢰 관련 표준과 규격이 존재한다.

따라서 다음과 같은 표현은 피해야 한다.

> “우리가 최초로 치기공 표준을 만든다.”
> 

우리가 만들고자 하는 것은 기존 국제표준을 대체하는 것이 아니다.

우리가 정의하고자 하는 영역은 다음과 같다.

> **한국 치기공 교육·제작 현장에서 실제로 케이스를 제작하기 전에 무엇이 존재해야 하며, 무엇을 확인해야 하고, 어떤 경우 제작을 중단해야 하는가에 대한 검증 기준**
> 

따라서 다음과 같은 표현이 적절하다.

- 치기공 제작 전 검증 기준
- 치기공 디지털 오류 분류체계
- 최소 제작 정보 세트
- 치기공 케이스 데이터 스키마
- 교육용 제작 전 검증 루브릭
- 치기공 제작 데이터 검증 프로파일

# 14. 데이터 거버넌스와 책임 구조

협력 논의에서 교수자가 가장 먼저 확인할 것은 가치가 아니라 리스크다. 따라서 데이터의 흐름, 책임, 소유권을 제안 단계에서 먼저 명확히 한다.

## 14.1 익명화 2단계 원칙

| 단계 | 주체 | 내용 |
| --- | --- | --- |
| 1차 비식별화 | 신구대 | 환자 성명·차트번호 등 직접 식별자를 제거 또는 가명 처리한 상태로 전달한다. 학교 내부 규정 기준을 따른다. |
| 2차 익명화 | DentalSync | 파이프라인 내 익명화 단계에서 파일명·메타데이터·자유서술 필드의 잔여 식별 요소를 제거한다. 처리 로그를 보관해 검증 가능 상태로 유지한다. |

원칙: **식별 가능 상태의 원본은 DentalSync로 이동하지 않는다.** 이 원칙이 신구대의 리스크를 구조적으로 차단하는 첫 번째 장치다.

## 14.2 사전 확인 항목 (`확인 필요`)

- 학생 실습 케이스에 포함된 환자 유래 스캔 데이터가 학교 기준상 IRB 심의 대상인지
- 익명화된 STL·의뢰서의 외부 제공에 별도 내부 승인 절차가 필요한지
- 학생 산출물(판단 기록)의 활용에 학생 동의가 필요한지

이 세 가지는 첫 미팅에서 교수님께 직접 확인하며, 답에 따라 합의서 문구를 조정한다.

## 14.3 합의 구조: 경량 합의 → 정식 MOU

처음부터 정식 MOU를 요구하면 결정 단위가 커져 논의가 지연된다. 다음 2단계로 설계한다.

1. **1단계 — 파일럿 합의서**: 비밀유지, 데이터 사용 범위(본 협력 목적 한정), 익명화 원칙, 파일럿 범위와 기간만 담은 1~2쪽 합의서.
2. **2단계 — 산학협력 MOU**: 파일럿 결과 리포트 공유 후, 데이터셋 공동 구축·소유·활용을 담은 정식 MOU로 확장한다.

## 14.4 소유권과 성과물

- 구축되는 구조화 데이터셋은 **신구대와 DentalSync의 공동 소유**로 한다.
- 신구대는 교육·연구 목적으로, DentalSync는 검증 시스템 고도화 목적으로 각자 활용할 수 있다. 제3자 제공은 상호 동의를 전제로 한다.
- 학술 논문·발표는 **옵션으로 제안**한다. 교수진이 원할 경우 공동 저자 구조로 적극 지원하되, 협력의 필수 조건으로 걸지 않는다. 논문 여부와 무관하게 실습 오류 분석 리포트는 반드시 제공한다.

# 15. 1단계 협력 제안

전체 비전을 한 번에 제안하면 상대의 결정 단위가 커진다. 소개받은 교수님을 접점으로, 다음 계단 구조로 진행한다.

## 15.1 계단 구조

| 단계 | 내용 | 산출물 | 결정 주체 |
| --- | --- | --- | --- |
| 0. 첫 미팅 | 소개 교수님과 문제의식 공유, 사전 확인 항목 3개 질의 | 파일럿 범위 합의 | 교수님 개인 |
| 1. 파일럿 | 한 과목·한 학기, 익명화 케이스 **20~30건** + 교수자 판단 라벨 | 실습 오류 분석 리포트 1회 | 교수님 + 학과 |
| 2. 확장 | 리포트 결과 공유 후 정식 MOU, 데이터 구조·분류체계 공동 구축 | 데이터셋·루브릭·분류체계 | 학과·산학협력단 |

## 15.2 첫 미팅에서 요청하는 것 (이것만)

- 파일럿 범위에 대한 동의 (케이스 20~30건, 한 학기)
- 사전 확인 항목 3개에 대한 답 (IRB·내부 승인·학생 동의)
- 케이스를 확보할 수 있는 과목·시점 확인

첫 미팅에서 MOU, 논문, 장기 데이터셋 구축은 **언급하되 요청하지 않는다.** 리포트라는 실물이 나온 뒤에 제안해야 설득 비용이 낮다.

## 15.3 우리가 첫 미팅 전에 준비할 것

- 판단 입력 양식 시안 (체크리스트 + 오류 코드)
- 리포트 샘플 목업 1쪽 (파일럿 결과물이 어떤 모습인지 보여주는 용도)
- 파일럿 합의서 초안
- 케이스당 라벨링 소요 시간 실측치 (팀 내부에서 샘플 1건 측정)

# 21. 최종 결론

신구대 협력의 핵심은 단순한 데이터 제공 요청이 아니다.

신구대에는 실제 치기공 실습 케이스와 교수진의 전문지식이 있다.

그러나 이러한 경험과 판단은 개별 수업과 개별 교수자의 경험 안에 존재하며, 교육과 연구에서 반복적으로 활용할 수 있는 **구조화된 데이터 형태로 축적되기 어렵다.**

DentalSync는 이를 다음과 같이 변환한다.

| 기존 자산 | 구조화 결과 |
| --- | --- |
| 실습 경험 | 구조화된 케이스 데이터 |
| 교수자의 판단 | 검증 기준 데이터 |
| 학생의 실수 | 오류 데이터 |
| 수정·재작업 | 결과 데이터 |
| 반복되는 경험 | 연구 가능한 데이터셋 |

따라서 우리가 신구대에 제공하는 가장 큰 가치는 다음과 같다.

> **치기공 교육 현장에서 발생하는 경험을 사라지는 경험으로 두지 않고, 치기공학계가 연구하고 교육할 수 있는 데이터 자산으로 남기는 것.**

# 22. [내부 전용] North Star 연결과 데이터의 한계

> 본 장은 팀 내부 판단 기준이다. 제안서로 변환할 때 반드시 제외한다.
> 

## 22.1 이 협력이 유료 LOI 2건에 기여하는 경로

신구대는 유료 고객이 아니다. 이 협력에 리소스를 쓰는 이유는 다음 두 가지로 한정한다.

1. **파일럿 go/kill 검증 데이터 공급원.** 필드 정확도 70% 기준을 검증하려면 라벨링된 실데이터가 필요하다. 교수자 판단이 붙은 케이스는 정답지가 있는 검증 세트다.
2. **보수적 시장에서의 신뢰 시그널.** 레퍼럴 중심 시장에서 “치기공 교육기관과 공동 구축”은 LOI 영업에서 쓸 수 있는 자산이다. fake door 실패의 진단(신뢰 신호 부족)에 대한 직접적 대응이기도 하다.

이 두 목적에 기여하지 않는 산출물(예: 장기 데이터 스키마 정교화)은 8월 우선순위에서 뒤로 미룬다.

## 22.2 실습 데이터의 한계 (외부에 주장하지 않을 것)

학생 실습 케이스의 오류 분포는 실제 기공소와 다르다. 현장 리메이크의 상당수는 치과발 휴먼에러이며, 실습 환경에서는 이 분포가 재현되지 않는다. 따라서 이 데이터의 용도는 다음으로 한정한다.

- OCR·검증 파이프라인의 필드 정확도 검증
- 교육용 산출물(루브릭·분류체계) 구축

**“현장 오류 감소 효과를 검증했다”는 주장의 근거로 쓰지 않는다.** 이 주장은 실제 기공소 파일럿에서만 가능하다.
