## 0. 한 줄 정의

**CrownOps by Paraegis** = 치과기공소가 디자인/제작 작업에 들어가기 전, 의뢰서·STL 파일·재료·쉐이드·임플란트/스캔바디 정보가 서로 맞는지 확인해 "작업 가능 / 검증 필요 / 재문의"로 케이스를 분류하는 **제작 전 정보 검증 체크게이트(B2B SaaS)**. ERP·MES를 대체하지 않고, 기존 운영 방식 위에 얹는 보완적 검증 레이어.

### 작업 스타일 / 협업 원칙 (중요 — 항상 준수할 것)

1. 한국어로 짧고 직접적으로 소통함. 여러 옵션을 늘어놓기보다 **명확한 하나의 추천**을 원함.
2. "진행해"라는 지시가 오면: 중간 확인 없이 **끝까지 자율적으로 실행**, 불확실하거나 모호한 부분은 스스로 합리적 가정을 세워서 진행.
3. **디자인/기획성 작업은 계획을 먼저 제시 → 확인받고 실행.** (과거에 "계획과 실행을 섞지 말라"고 명확히 지적받은 패턴 — 계획 단계에서 바로 결과물까지 만들어버리면 안 됨)
4. 산출물 포맷: 파일/무거운 마크다운보다 **깔끔한 pasteable 텍스트**를 원하는 경우가 많음 (예: "아니 그냥 텍스트로 깔끔하게 정리해"). 제품/사업 문서는 **개조식(구조화된 불릿)** 포맷을 선호.
5. 오류 수정 시 직접적이고 간결하게 지적함 (예: "CloseUp이 아니라 ClothUp", "치과가 리메이크 원인이지 직원 탓이 아니다") → 지적받으면 **관련된 모든 자료에 즉시, 재확인 없이** 반영.
6. 근거 없는 숫자를 만들어내는 것을 극도로 경계함 — 검증 안 된 추정치는 반드시 "추정치"라고 명시하고, 파일럿/실측을 통해 검증하는 절차를 중요하게 여김.
7. 스스로 세운 루브릭으로 결과물을 엄격히 검증하고, 기준 미달 시 처음부터 다시 만드는 방식 선호 (완벽주의적 반복 접근).

## 3. 핵심 문제 정의 (사업계획서의 논리적 출발점)

> **치과기공소 리메이크의 근본 원인은 치과 측이 제공하는 불완전/부정확한 의뢰 정보이지, 기공소 직원의 입력 오류가 아니다.**

- 이 프레이밍은 모든 제품·연구·커뮤니티 커뮤니케이션에서 반드시 일관되게 유지되어야 하는 **핵심 전제**임.
- 치과기공소에는 의뢰서, STL 파일, 재료 조건, 쉐이드, 스캔바디 정보가 카카오톡·이메일·스캐너 연동(3Shape, Medit 등) 등 여러 채널로 흩어져 들어옴.
- 담당자가 이를 수동으로 취합·확인하는 과정에서 누락·불일치가 발생 → 늦게 발견될수록 리메이크, 납기 지연, 치과와의 신뢰 저하로 이어짐.
- 문제 → 해법 → 결과 논리:
  1. **문제**: 정보가 여러 채널로 흩어져 있고, 수동 확인에 의존하다 오류가 늦게 발견됨
  2. **해법**: CrownOps가 제작 직전 단계에 개입해 "지금 이 케이스를 작업해도 되는가"를 체크
  3. **포지셔닝**: ERP·MES·전자의뢰서·청구·CAD/CAM 자동화가 아님. 대체가 아니라 마지막 검증 관문. "관리"가 아니라 "검증"이 핵심 차별점

## 4. 제품 구조

### 핵심 기능
- 의뢰서 확인 (정식 의뢰서 존재 여부)
- STL 파일 확인 (도착·중복·누락 여부)
- 의뢰서–STL 매칭 (환자명·치아번호·케이스 정보 기준)
- 재료 검증 (제작 재료 정보 누락 확인)
- 쉐이드 검증 (누락·불명확 여부)
- 스캔바디/임플란트 정보 확인
- 외부 검증 요청 분리 / 최종 확인 요청 분리
- 케이스 상태 분류: **작업 가능 / 검증 필요 / 재문의**

### 대시보드 구조
- 열 구성: 케이스 → 거래처 → 작업 → 검증 → 공정단계 → 상태
- 상태 용어는 의도적으로 "오류/불량/치과 확인 필요/소장 확인 필요" 같은 부정적·책임전가성 표현을 피하고, **"검증 필요 / 외부 검증 요청 / 최종 확인 필요"**로 완충 — 현장에서 반감 없이 쓰이게 하려는 설계

### 5단계 워크플로우 (브로슈어용 압축 버전, 원래 PPT 10단계를 압축)
의뢰 수신 → 케이스 정리 → 파일 매칭 → 작업 전 확인 → 체크게이트

### 타깃 고객
- 핵심 타깃: 한국 치과기공소 — **기공소장**, **CAD/CAM 디자이너**
- 케이스 수가 많아 담당자 수동 확인 부담이 큰 기공소
- 여러 치과와 거래하며 의뢰 정보가 분산되는 기공소
- 리메이크를 줄이고자 하는 성장형 기공소

- **실제 시장 가격 구조**:

| 프로그램 | 가격 | 방식 |

| 대한치과기공사협회 "dentallab" | **무료** | 협회가 회원 기공소에 직접 배포 |
| 사무장 (성원정보기술) | 일시불 구매(비공개) | 구형 라이선스 |

| 클레버랩(바텍) | 비공개 | 장비 고객 대상 번들 가능성 |

- **시사점**: 이 시장은 "장부 관리 프로그램"에 익숙하고 가격 기준선이 월 2만원~무료. CrownOps는 다른 카테고리(정보 검증)지만 소장 입장에서는 "또 하나의 소프트웨어 구독료"로 인식될 위험이 큼.
- **두 가지 전략 시나리오**:
  1. 저가 진입: 월 3~5만원 (장부 프로그램 가격대 + 알파)
  2. 가치 기반 고가: 리메이크 1건 방지 = 재료비+인건비 손실 방지라는 손실 회피 가치로 정당화 (단, 리메이크 손실액 정량 데이터 필요 — 신구대 파일럿에서 확보 예정)
- 결론: 파일럿 실측 전까지는 **"저가 벤치마크(월 3~5만원) vs 가치기반 가정(월 15~20만원)"** 두 시나리오를 병기하는 것이 정직한 접근.

## 6. 시장 분석 (TAM/SAM/SOM)

### 방법론 확정 사항
- **단위 기반(개소 수) 산정**을 매출 기반보다 우선함 — ARPU가 미검증이기 때문
- SAM ≈ SOM이 되는 구조적 오류를 피하기 위해 이준우 멘토 지적에 따라 SAM은 국가 전체, SOM은 5인 이상 디지털 워크플로우 세그먼트로 분리
- 국가 선정 기준은 "동일 법제"가 아니라 **"위탁 제작 산업 구조"** — 독일·영국은 한국의 비영리 의료법인 소유 제한 구조를 공유하지 않음

### 확정된 한국 시장 규모 (5개국 중 실행 근거 있는 유일한 시장)

|---|---|---|
| TAM (5개국 합산) | 34,970개소 | 5개국 치과기공소 총합 |

## 8. Go-to-Market 현황 및 전략 피벗

### 직접 아웃리치 정체 → 원인 진단
- 기공소장 대상 직접 아웃리치(이메일·전화·무접촉 파일 요청 — "케이스 3개만 무료 검토")를 시도했으나 응답 후 후속 연락이 끊기는 패턴 반복
- 구조화된 가설 소거 결과, 원인 후보 5가지:
  - A. 완성품 원함(파일럿 여력 없음) — 주원 본인의 가설
  - B. 메일이 도달 안 하거나 무시됨
  - C. 처음 보는 회사의 SaaS에 대한 신뢰 부족
  - D. 지금 당장 아픈 문제가 아닌 "있으면 좋은" 정도로 인식
  - E. 요청이 모호해서("파일럿 참여" 자체가 부담스러움) 구체적 범위 축소 필요
- **결론: A만 검증된 게 아니라 B~E도 가능성이 있으므로, 신구대 피벗과 별개로 응답 기공소 재접촉(전화/카톡, 요청 크기 축소)을 병행 검증해야 함**

### 확정된 전략 피벗 — 두 트랙
1. **교육 파일럿 (신구대학교 치기공과)**
   - 가천대 교수 네트워크를 통한 신구대 치기공과 교수 소개 대기 중
   - 목적: 정량적 리메이크/손실 데이터를 정직하게 수집하는 메커니즘 (숫자 조작 없이)
   - 리스크: 학생 실습 케이스가 실제 임상보다 단순하거나 채널 혼재 문제가 재현 안 될 수 있음 → 실습 설계 시 의도적으로 정보를 여러 경로(카톡 캡처, 이메일 첨부, 손글씨 메모)로 흩어서 재현할 것을 권고받음
   - 기다리는 동안 병행 권고: A~E 가설 직접 검증(응답 기공소 재접촉), 성공 기준 사전 정의("체크리스트 항목 중 학생이 스스로 놓치는 비율" 등)
2. **커뮤니티 검증 (덴탈2804)**
   - 완전히 기공소 직원인 척(참여관찰) 하여 구조적 문제(치과발 정보 오류)를 매핑하고 앵커링 기법으로 빈도/규모 데이터 추출
   - 초기 게시글은 "직원 실수" 프레임으로 시작했으나, **치과 측 정보 누락/오류가 리메이크 원인이라는 것이 핵심 전제이므로 이 방향으로 프레임을 전환함**
   - 초기 반응(3개 댓글)은 문제 자체는 인정하나 원인을 "개인 책임감/의지"로 돌리는 패턴 → 후속 전략: 반박하지 않고 "저도 해봤는데 한계가 있더라"는 경험담으로 위장해 상대 해결책의 실효성을 되묻고, 빈도 숫자를 자연스럽게 먼저 던져 앵커링 유도
   - 운영 팁: 여러 게시글을 동일 계정으로 동시에 올리지 않고 며칠 간격/계정 분리, 댓글 반응(수·내용·날짜)을 캡처해 출처·시점과 함께 기록해 추후 사업계획서 근거자료로 사용

2. **B2C 레버리지 B2B 진입** — 덴탈2804 등에서 참여관찰(잠입)로 문제를 직접 검증한 뒤 B2B 영업에 활용
3. **정량 지표 표준화 (핵심 강조)** — 네트워크 입증 자료, 손실 자료(기공소·치과 계약 파기 데이터), 가격 손실 데이터를 최대한 표준화. BM을 잘 짤 것. 초기 진입 시장을 더 세분화해도 됨(선택)
4. **미션/비전 재검토** — 굳이 넣을 필요 없음, 현재 CrownOps와 미션/비전이 잘 안 맞아 보임. 넣으려면 정말 잘 맞아야 하고 "울림"이 있어야 함. 현재 미션/비전을 말하려면 다른 의료 분야에도 치기공과 유사한 병목이 있어야 하는데, 검증 전에 타 의료분야로 확장을 논하는 건 너무 이른 생각 — 지금은 CrownOps 자체의 확장(시장 확장과 제품 확장을 구분)에 집중해야 함

## 10. 사업계획서 구조 (PSST 프레임)

멘토링·정부지원사업(하나 소셜벤처 유니버시티, 가천대 연계, 사회적기업가 육성사업/초기창업패키지 등) 맥락에 맞춰 **PSST(문제인식-실현가능성-성장전략-팀구성)** 구조 채택.

1. **문제인식 (Problem)**
   - 1-1. 문제 정의: 리메이크의 근본 원인 = 치과 측의 불완전/부정확한 의뢰 정보 (기공소 직원 오류 아님)
   - 1-2. AS-IS 프로세스: 현재 기공소 검증 프로세스가 수작업/구두 확인에 의존하는 양상 구체적 서술 (멘토 1축)
   - 1-3. 정량적 근거: 리메이크 발생 빈도·손실 데이터 (신구대 파일럿 + 덴탈2804에서 확보 예정)
   - 주의: 이 섹션에는 미션/비전, 제품 기능 소개 넣지 않기 — 순수하게 "문제"만
2. **실현가능성 (Solution)**
   - 2-1. 솔루션 개요: 체크게이트, ERP/MES 대체 아닌 보완 레이어 포지셔닝 명확히
   - 2-2. 차별성/기술력: STL·재료·쉐이드·임플란트/스캔바디 매칭 검증 로직
   - 2-3. 검증 실적: 신구대 파일럿 진행 현황 — 없는 숫자 지어내지 않고 "진행 중"이면 그대로 기재
   - 2-4. 신뢰 확보 전략: 데이터 민감성 대응 — 개인정보/보안 정책, 트러스트 시그널(사업자등록, 회사 연혁)
3. **성장전략 (Scale-up)**

   - (이후 섹션은 대화 절단으로 미확보 — 이어서 확인 필요 시 재작업)
4. **팀구성 (Team)** — 상세 미확보
