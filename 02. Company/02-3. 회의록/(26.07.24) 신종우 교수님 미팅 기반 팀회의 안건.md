# 신종우 교수님 미팅 기반 팀회의 안건

## 1. 회의 개요

- **회의명:** 신종우 교수님 자문 기반 CrownOps 방향성 재검토 회의
- **참석자:** 신은지, 엄주원
- **권장 소요 시간:** 2시간~2시간 30분
- **회의 목적**
    1. 교수님 피드백을 사실과 의견으로 구분한다.
    2. CrownOps의 기존 문제정의와 가치제안을 재검토한다.
    3. 리메이크의 실제 주요 원인이 무엇인지 검증할 계획을 수립한다.
    4. CrownOps를 유지·수정·확장할 범위를 결정한다.
    5. 치과기공사 실기시험 AI 채점 아이디어를 별도 사업 실험으로 진행할지 결정한다.
    6. 다음 2주 동안 실행할 검증 과제를 확정한다.

# 4. 상세 회의 안건

## 안건 1. 교수님 피드백의 핵심 내용 정리

### 논의 목적

교수님의 발언을 그대로 받아들이거나 감정적으로 반응하지 않고, 사업 판단에 사용할 수 있는 가설로 정리한다.

### 교수님 핵심 주장

1. 치과 보철물 리메이크의 주요 원인은 의뢰서보다 인상·스캔·바이트 등 앞단 데이터일 가능성이 높다.
2. 의뢰서 누락이나 재료·쉐이드 오류는 전화나 작업 전 확인으로 해결되는 경우가 많다.
3. 기공사는 문제가 있는 데이터를 받아도 치과와의 갑을관계 때문에 작업을 거절하기 어렵다.
4. 기공소 시장은 영세하고 도입 저항이 크기 때문에 직접적인 SaaS 판매가 쉽지 않을 수 있다.
5. 실제 임상 데이터는 환자마다 정답이 달라 AI 검증이 기술적으로 어렵다.
6. 반면 교육·시험 환경은 기준 모델이 존재해 AI 채점이 상대적으로 가능하다.
7. CrownOps 하나에만 매달리지 말고 여러 아이디어를 빠르게 실험할 필요가 있다.

### 구분해야 할 것

|구분|내용|
|---|---|
|사실에 가까운 내용|인상·스캔·바이트 오류가 리메이크 원인이 될 수 있음|
|추가 검증이 필요한 주장|의뢰서 오류는 리메이크에서 비중이 작음|
|교수님 개인적 전망|장기적으로 기공소·기공사 역할이 축소될 가능성|
|사업적 조언|작은 기공소보다 기관 고객을 대상으로 하는 것이 나을 수 있음|
|신규 아이디어|실기시험 3D 스캔 기반 AI 채점 시스템|

### 논의 질문

- 교수님의 피드백 중 우리가 가장 동의하는 부분은 무엇인가
- 동의하기 어려운 부분은 무엇인가
- 교수님의 경험이 현재 전체 시장을 대표한다고 볼 수 있는가
- 현직 소장 1명의 의견을 일반화해도 되는가
- 우리가 기존 인터뷰에서 확인한 내용과 충돌하는 지점은 무엇인가

### 회의 결과물

- 동의하는 피드백
- 검증이 필요한 피드백
- 수용하지 않을 피드백

세 가지로 구분한다.

## 안건 2. CrownOps의 기존 문제정의 재검토

### 기존 문제정의

> 치과에서 전달되는 의뢰서, STL 파일, 재료·쉐이드·임플란트 정보가 서로 분리되어 전달되고, 기공소가 이를 수작업으로 매칭하는 과정에서 누락과 불일치가 발생해 리메이크와 손실이 발생한다.

### 교수님 피드백을 반영한 새로운 문제 후보

> 치과에서 전달된 인상·스캔·바이트 데이터에 문제가 있어도 기공소가 이를 객관적으로 판별하거나 치과에 반려하기 어려워, 제작을 진행한 후 리메이크 비용을 부담한다.

### 비교 논의

|구분|기존 문제|수정 문제|
|---|---|---|
|문제 발생 지점|의뢰 정보 전달·매칭|인상·스캔·바이트 생성|
|핵심 오류|누락·불일치·매칭 오류|제작 불가능하거나 부정확한 원본 데이터|
|현재 해결 방법|전화·카톡·수작업 확인|기공사 육안 판단·경험|
|주요 피해자|기공소 직원·소장|기공소·치과·환자|
|지불 가능성|불확실|불확실하지만 손실 규모가 더 클 가능성|
|기술 난이도|비교적 낮음|매우 높음|
|경쟁 강도|관리 프로그램과 중첩|전문 AI·스캔 기술과 중첩 가능|

### 핵심 논의 질문

- 우리가 해결하고 싶은 문제는 ‘정보 누락’인가, ‘제작 불가능 데이터’인가
- 실제 기공소가 더 큰 비용을 지불하는 문제는 무엇인가
- 의뢰서 문제를 해결하면 리메이크가 실제로 얼마나 감소하는가
- 스캔 품질 문제를 해결하면 실제 리메이크가 얼마나 감소하는가
- 고객이 현재 가장 자주 겪지만 해결하지 못하는 문제는 무엇인가
- 기존 문제정의가 틀린 것인가, 아니면 문제 범위가 좁았던 것인가

### 결정해야 할 선택지

#### 선택지 A. 기존 문제 유지

의뢰서·파일·재료 조건 매칭을 핵심으로 유지한다.

조건:

- 실제 현장에서 자주 발생한다는 증거
- 손실 비용이 명확함
- 경쟁사 대비 차별성이 있음
- 고객이 비용을 지불할 의향이 있음

#### 선택지 B. 문제 범위 확장

의뢰서 검증에 스캔 품질 검증을 추가한다.

```
의뢰 정보 검증
+
스캔 데이터 품질 검증
+
제작 가능 여부 판단
```

#### 선택지 C. 핵심 문제 전환

의뢰서 매칭은 보조 기능으로 낮추고 스캔·바이트·마진 품질 검증을 핵심으로 전환한다.

#### 선택지 D. CrownOps 중단

시장성, 기술성, 고객 지불 의사가 모두 부족할 경우 프로젝트를 종료하거나 보류한다.

## 안건 3. 리메이크 원인에 대한 근거 재검증

### 논의 목적

현재 사업계획서에서 주장하는 리메이크 원인과 해결 효과가 실제로 근거가 있는지 확인한다.

### 현재 우려

- 63.7%라는 수치를 잘못 해석했을 가능성
- 치과 원인과 의뢰서 원인을 동일하게 해석했을 가능성
- 수정과 완전 재제작을 구분하지 않았을 가능성
- 아날로그와 디지털 케이스를 한데 묶었을 가능성
- 치과·기공소·환자 원인을 명확히 나누지 않았을 가능성

### 리메이크 원인 분류안

1. 치과 임상 단계
    - 프렙 문제
    - 인상 채득 오류
    - 구강스캔 오류
    - 바이트 오류
    - 마진 불명확
    - 스캔바디 오류
2. 정보 전달 단계
    - 의뢰서 누락
    - 재료·쉐이드 누락
    - 환자·치아번호 매칭 오류
    - STL 파일 누락·중복
    - 잘못된 파일 전송
3. 기공 제작 단계
    - CAD 설계 오류
    - 밀링·프린팅 오류
    - 소결·수축률 오류
    - 작업자 실수
    - 재료 선택 오류
4. 배송·납품 단계
    - 환자 케이스 오배송
    - 라벨 오류
    - 치과별 분류 오류
5. 치과 장착 단계
    - 교합 조정 문제
    - 시멘트·장착 문제
    - 환자 구강 상태 변화

### 조사 시 반드시 분리할 기준

- 완전 재제작 / 현장 수정
- 아날로그 / 디지털
- 단일 크라운 / 브릿지 / 임플란트
- 치과 원인 / 기공소 원인 / 공동 원인
- 작업 전 발견 / 제작 후 발견
- 비용 발생 / 비용 미발생

### 추가 인터뷰 질문

- 최근 완전 재제작 사례 10건의 원인은 무엇이었는가
- 리메이크 전 작업자가 문제를 알고 있었는가
- 알고도 작업했다면 이유는 무엇인가
- 치과에 재인상·재스캔을 요청한 비율은 어느 정도인가
- 의뢰서 오류로 실제 재제작한 사례는 몇 건인가
- 스캔 오류로 실제 재제작한 사례는 몇 건인가
- 문제 케이스를 자동으로 판별해준다면 비용을 지불할 의향이 있는가
- 오류 리포트가 있다면 치과에 재스캔을 요청하기 쉬워지는가

### 회의 결과물

- 인터뷰 대상 수
- 대상 기공소 유형
- 질문지 담당자
- 조사 마감일
- 판단 기준

을 정한다.

## 안건 4. CrownOps의 핵심 가치제안 수정 여부

### 기존 가치제안

> 의뢰서와 제작 파일의 누락·불일치를 제작 전에 검증해 리메이크와 손실을 줄인다.

### 수정 후보 1

> CrownOps는 치과에서 전달된 데이터가 실제 제작 가능한 상태인지 확인해, 잘못된 데이터로 제작을 시작하지 않게 합니다.

### 수정 후보 2

> CrownOps는 인상·스캔·바이트·의뢰 정보를 제작 전에 검증하고, 제작 가능한 케이스와 재확인이 필요한 케이스를 구분합니다.

### 수정 후보 3

> 기공사의 경험과 감에 의존하던 제작 가능 판단을 데이터로 바꿉니다.

### 논의 질문

- 고객은 리메이크 감소에 돈을 내는가
- 고객은 시간 절약에 돈을 내는가
- 고객은 책임소재 기록에 돈을 내는가
- 고객은 치과에 객관적으로 반려할 근거에 돈을 내는가
- 고객이 가장 강하게 반응할 문장은 무엇인가

### 결정 사항

핵심 가치를 하나만 선택한다.

- 리메이크 감소
- 제작 전 오류 방지
- 치과 재확인 자동화
- 객관적 반려 근거
- 작업자 판단 부담 감소
- 책임소재 기록

여러 가치를 동시에 주장하지 말고, 초기에는 하나를 중심으로 잡는다.

## 안건 5. 제품 범위와 MVP 재설계

### 현재 기능

- 의뢰서 존재 여부 확인
- STL 파일 도착 여부 확인
- 의뢰서와 파일 매칭
- 재료·쉐이드·임플란트 정보 확인
- 검증 필요 상태 표시
- 외부 검증 요청
- 최종 확인 요청
- 배송 라벨 확인

### 추가 검토 기능

- 마진 명확도 분석
- 스캔 누락 탐지
- 데이터 홀 탐지
- 중복 스캔 탐지
- 대합치 파일 확인
- 바이트 파일 확인
- 스캔바디 위치 확인
- 재스캔 필요 여부 판단
- 제작 가능 점수
- 문제 부위 시각화
- 치과 전달용 오류 리포트

### 기능 분류

#### 반드시 남길 기능

현재 고객 문제와 직접 연결되고 개발 가능성이 높은 기능

#### 추가 검증이 필요한 기능

고객 가치는 높지만 기술 검증이 필요한 기능

#### 당장 제외할 기능

복잡도는 높지만 초기 고객 가치가 낮은 기능

### MVP 후보

#### MVP 1. 수작업 검증 서비스

실제 케이스를 받아 사람이 직접 의뢰서와 파일을 확인한다.

목적:

- 오류 발생 빈도 확인
- 고객 반응 확인
- 검증 리포트 가치 확인

#### MVP 2. 규칙 기반 스캔 검사

AI 이전에 자동 규칙으로 확인한다.

예:

- 필요한 STL 파일 수 확인
- 대합치 파일 존재 여부
- 바이트 파일 존재 여부
- 파일명·환자명 매칭
- 파일 크기·손상 여부
- 스캔 데이터 홀 여부

#### MVP 3. AI 스캔 품질 분석

3D 데이터에서 마진·누락·스캔 품질을 분석한다.

주의:

- 기술 난이도 높음
- 의료기기 규제 가능성
- 충분한 학습 데이터 필요

### 회의 결정

- 1차 MVP 범위
- 2차 MVP 범위
- 개발하지 않을 기능
- 각 기능의 검증 기준

을 정한다.

## 안건 6. 고객과 구매자 재검토

## 안건 7. 치과기공사 실기시험 AI 채점 아이디어 평가

### 아이디어 정의

> 기준 보철물과 응시자 제작물을 3D 스캔해 형태 편차를 분석하고, 평가위원에게 점수와 오류 정보를 제공하는 AI 기반 실기시험 보조채점 시스템

### 해결하려는 문제

- 평가위원 간 채점 편차
- 육안 채점 의존
- 장시간 채점
- 구체적인 피드백 부족
- 평가 과정의 객관성·일관성 부족
- 대량 시험 운영의 인력 비용

### 고객 후보

- 한국보건의료인국가시험원
- 치기공학과
- 치과기공 관련 학원
- 학생
- 치과기공사 협회
- 해외 치과기공 교육기관

### 초기 제품 후보

#### 제품 A. 대학 실습 자동평가

교수가 학생 작품을 빠르게 평가하고 피드백하는 서비스

#### 제품 B. 국가시험 대비 모의채점

학생이 작품을 스캔해 예상 점수와 약점을 확인하는 서비스

#### 제품 C. 국시원 평가위원 보조도구

평가위원에게 정량적 분석 결과를 제공하는 시스템

### 기술 구성

```
기준 모델 제작
↓
응시자 작품 3D 스캔
↓
기준 모델과 자동 정렬
↓
부위별 형상 편차 분석
↓
채점 항목별 점수 제안
↓
평가위원 최종 확인
↓
평가 리포트 생성
```

### 검증해야 할 핵심 가설

1. 치과기공사 실기시험에 명확한 기준 모델이 존재하는가
2. 현재 평가기준을 정량적 수치로 변환할 수 있는가
3. 3D 형상만으로 전체 평가항목을 측정할 수 있는가
4. 표면 마감과 심미성을 이미지로 평가할 수 있는가
5. 교수들의 평가점수와 AI 측정값 사이에 상관관계가 있는가
6. 대학이 실제 비용을 지불할 의향이 있는가
7. 국시원이 기존 채점 방식을 개선하려는 의지가 있는가
8. 교수님의 기존 특허와 충돌하거나 활용 가능한 부분이 있는가

### 주요 리스크

- 국가시험 평가기준 비공개
- 평가위원·학계의 저항
- 정답 모델의 타당성 논쟁
- 시험 과제마다 별도 모델 필요
- 스캐너 오차
- 표면·심미성 평가의 한계
- 국시원 조달과 긴 의사결정 기간
- 특허권과 기술 소유권 문제

### Go / No-Go 기준

다음 조건을 충족하면 실험을 진행한다.

- 교수 5명 이상 중 3명 이상이 필요성에 동의
- 학생 20명 이상 중 50% 이상이 사용 의향 표시
- 기존 채점 결과와 3D 편차 간 유의미한 연관 확인
- 한 가지 실기 과제를 기준으로 프로토타입 제작 가능
- 대학 1곳 이상에서 실습 테스트 협조

## 안건 8. CrownOps와 AI 채점 아이템의 관계 결정

### 선택지 1. CrownOps에 집중

AI 채점 아이템은 조사만 하고 당분간 보류한다.

적합한 상황:

- CrownOps 고객 수요가 명확함
- 파일럿 도입처가 확보됨
- 기존 기능으로 손실 감소를 증명할 가능성이 높음

### 선택지 2. 두 개 트랙 병행

- 트랙 A: CrownOps 고객·문제 검증
- 트랙 B: AI 채점 아이디어 기술·수요 검증

주의:

2인 팀이므로 개발을 동시에 두 개 진행하면 안 된다.

두 트랙 모두 초기에는 인터뷰·데이터 확인·프로토타입 수준으로 운영한다.

### 선택지 3. AI 채점으로 전환

CrownOps를 보류하고 AI 채점 아이템에 집중한다.

전환 조건:

- CrownOps 고객 지불 의사가 낮음
- 의뢰서 문제가 리메이크의 핵심 원인이 아님
- 스캔 품질 검증은 기술적으로 너무 어려움
- AI 채점은 대학·교수·기관의 수요가 명확함
- 데이터 확보와 실증 파트너가 존재함

### 추천 원칙

현재 단계에서는 즉시 전환보다 **2주간 두 가설을 동시에 검증한 뒤 비교**하는 것이 적절하다.

## 안건 4. CrownOps의 핵심 가치제안 수정 여부

### 기존 가치제안

> 의뢰서와 제작 파일의 누락·불일치를 제작 전에 검증해 리메이크와 손실을 줄인다.

### 수정 후보 1

> CrownOps는 치과에서 전달된 데이터가 실제 제작 가능한 상태인지 확인해, 잘못된 데이터로 제작을 시작하지 않게 합니다.

### 수정 후보 2

> CrownOps는 인상·스캔·바이트·의뢰 정보를 제작 전에 검증하고, 제작 가능한 케이스와 재확인이 필요한 케이스를 구분합니다.

### 수정 후보 3

> 기공사의 경험과 감에 의존하던 제작 가능 판단을 데이터로 바꿉니다.

### 논의 질문

- 고객은 리메이크 감소에 돈을 내는가
- 고객은 시간 절약에 돈을 내는가
- 고객은 책임소재 기록에 돈을 내는가
- 고객은 치과에 객관적으로 반려할 근거에 돈을 내는가
- 고객이 가장 강하게 반응할 문장은 무엇인가

### 결정 사항

핵심 가치를 하나만 선택한다.

- 리메이크 감소
- 제작 전 오류 방지
- 치과 재확인 자동화
- 객관적 반려 근거
- 작업자 판단 부담 감소
- 책임소재 기록

여러 가치를 동시에 주장하지 말고, 초기에는 하나를 중심으로 잡는다.

## 안건 5. 제품 범위와 MVP 재설계

### 현재 기능

- 의뢰서 존재 여부 확인
- STL 파일 도착 여부 확인
- 의뢰서와 파일 매칭
- 재료·쉐이드·임플란트 정보 확인
- 검증 필요 상태 표시
- 외부 검증 요청
- 최종 확인 요청
- 배송 라벨 확인

### 추가 검토 기능

- 마진 명확도 분석
- 스캔 누락 탐지
- 데이터 홀 탐지
- 중복 스캔 탐지
- 대합치 파일 확인
- 바이트 파일 확인
- 스캔바디 위치 확인
- 재스캔 필요 여부 판단
- 제작 가능 점수
- 문제 부위 시각화
- 치과 전달용 오류 리포트

### 기능 분류

#### 반드시 남길 기능

현재 고객 문제와 직접 연결되고 개발 가능성이 높은 기능

#### 추가 검증이 필요한 기능

고객 가치는 높지만 기술 검증이 필요한 기능

#### 당장 제외할 기능

복잡도는 높지만 초기 고객 가치가 낮은 기능

### MVP 후보

#### MVP 1. 수작업 검증 서비스

실제 케이스를 받아 사람이 직접 의뢰서와 파일을 확인한다.

목적:

- 오류 발생 빈도 확인
- 고객 반응 확인
- 검증 리포트 가치 확인

#### MVP 2. 규칙 기반 스캔 검사

AI 이전에 자동 규칙으로 확인한다.

예:

- 필요한 STL 파일 수 확인
- 대합치 파일 존재 여부
- 바이트 파일 존재 여부
- 파일명·환자명 매칭
- 파일 크기·손상 여부
- 스캔 데이터 홀 여부

#### MVP 3. AI 스캔 품질 분석

3D 데이터에서 마진·누락·스캔 품질을 분석한다.

주의:

- 기술 난이도 높음
- 의료기기 규제 가능성
- 충분한 학습 데이터 필요

### 회의 결정

- 1차 MVP 범위
- 2차 MVP 범위
- 개발하지 않을 기능
- 각 기능의 검증 기준

을 정한다.

```
평가 리포트 생성
```

### 검증해야 할 핵심 가설

1. 치과기공사 실기시험에 명확한 기준 모델이 존재하는가
2. 현재 평가기준을 정량적 수치로 변환할 수 있는가
3. 3D 형상만으로 전체 평가항목을 측정할 수 있는가
4. 표면 마감과 심미성을 이미지로 평가할 수 있는가
5. 교수들의 평가점수와 AI 측정값 사이에 상관관계가 있는가
6. 대학이 실제 비용을 지불할 의향이 있는가
7. 국시원이 기존 채점 방식을 개선하려는 의지가 있는가
8. 교수님의 기존 특허와 충돌하거나 활용 가능한 부분이 있는가

### 주요 리스크

- 국가시험 평가기준 비공개
- 평가위원·학계의 저항
- 정답 모델의 타당성 논쟁
- 시험 과제마다 별도 모델 필요
- 스캐너 오차
- 표면·심미성 평가의 한계
- 국시원 조달과 긴 의사결정 기간
- 특허권과 기술 소유권 문제

### Go / No-Go 기준

다음 조건을 충족하면 실험을 진행한다.

- 교수 5명 이상 중 3명 이상이 필요성에 동의
- 학생 20명 이상 중 50% 이상이 사용 의향 표시
- 기존 채점 결과와 3D 편차 간 유의미한 연관 확인
- 한 가지 실기 과제를 기준으로 프로토타입 제작 가능
- 대학 1곳 이상에서 실습 테스트 협조

## 안건 8. CrownOps와 AI 채점 아이템의 관계 결정

### 선택지 1. CrownOps에 집중

AI 채점 아이템은 조사만 하고 당분간 보류한다.

적합한 상황:

- CrownOps 고객 수요가 명확함
- 파일럿 도입처가 확보됨
- 기존 기능으로 손실 감소를 증명할 가능성이 높음

### 선택지 2. 두 개 트랙 병행

- 트랙 A: CrownOps 고객·문제 검증
- 트랙 B: AI 채점 아이디어 기술·수요 검증

주의:

2인 팀이므로 개발을 동시에 두 개 진행하면 안 된다.

두 트랙 모두 초기에는 인터뷰·데이터 확인·프로토타입 수준으로 운영한다.

### 선택지 3. AI 채점으로 전환

CrownOps를 보류하고 AI 채점 아이템에 집중한다.

전환 조건:

- CrownOps 고객 지불 의사가 낮음
- 의뢰서 문제가 리메이크의 핵심 원인이 아님
- 스캔 품질 검증은 기술적으로 너무 어려움
- AI 채점은 대학·교수·기관의 수요가 명확함
- 데이터 확보와 실증 파트너가 존재함

### 추천 원칙

현재 단계에서는 즉시 전환보다 **2주간 두 가설을 동시에 검증한 뒤 비교**하는 것이 적절하다.

7. 회의에서 결론이 나지 않는 것은 추가 검증 과제로 전환한다.
8. 두 아이템을 동시에 완성하려 하지 않고, 가장 싼 방식으로 먼저 검증한다.

# 10. 이번 회의의 최종 목표

이번 팀회의에서 CrownOps를 바로 포기하거나 AI 채점 아이템으로 즉시 전환할 필요는 없다.

가장 중요한 것은 다음 두 가설을 분리해 빠르게 검증하는 것이다.

### 가설 A

> 의뢰서·스캔·제작 데이터 검증은 기공소의 실제 리메이크와 손실을 줄일 수 있으며, 기공소는 이를 위해 비용을 지불한다.

### 가설 B

> 치과기공사 실기시험의 평가 편차와 채점 비효율은 실제 문제이며, 대학이나 국시원은 3D 스캔 기반 보조채점 시스템을 도입할 의향이 있다.

2주 동안 두 가설을 검증한 뒤, 더 강한 고객 수요와 실행 가능성이 확인되는 방향에 팀 자원을 집중한다.
